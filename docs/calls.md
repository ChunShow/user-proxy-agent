# 통화 연결

5단계 구현 완료. 모사 검증과 승인받은 본인 휴대폰 실통화 2회를 구분해 검증했다.

## 이식 출처

`../calling-agent/src/calling_agent`의 ClawOps control/connection/native,
Azure audio 세션, native_audio bridge, DTMF/end_call 계약을 필요한 범위만
`backend/src/agent_service/calls`에 이식했다. 관련 계약 테스트를 함께 옮겼다.
PCM 변환·Whisper·TTS·CLI·Journal은 가져오지 않았다. 형제 프로젝트 런타임 의존성은 없다.

G.711 μ-law 8kHz 음성을 ClawOps와 Realtime 사이에서 직접 전달한다. 서버 VAD의
끼어들기와 원격 재생 mark를 사용하며, 입력 음성 전사는 비활성화다.
음성 모델은 `send_dtmf`, `end_call`만 실행한다. 버튼 전송 성공은 메뉴 전환의 증거가 아니며,
종료 요청은 마지막 인사 재생 확인 후 서버가 회선 종료를 요청하는 동작이다.

`.env.example`의 `CALL_*`, `CLAWOPS_*`는 텍스트 모델 `MODEL_*`와 별도다.
기본적으로 통화는 비활성화이며, 발신 대상은 로컬 허용 목록으로 제한한다.
키·번호·음성 및 통화 결과는 Git에 넣지 않는다.

## 작업 수명과 복구

같은 사용자 요청 메시지는 통화 작업 하나만 만든다. DB에서 발신 시도를 먼저 기록하고
공급자 POST는 한 번만 시도한다. 공급자 idempotency key는 없으므로 응답 유실은 `unknown`으로
보존한다. 이 경우 새 발신을 막으며 운영자가 ClawOps에서 실제 회선을 확인해야 한다.

정상 종료는 회선을 정리하고, 재시작은 기존 공급자 ID의 회선만 조회·종료한다.
브라우저 종료와 채팅 중단은 별도다. 활성 상태 조회는 2초, 종료 확인은 최대 5회다.
DB 장애 직후에도 이미 얻은 공급자 ID로 직접 종료를 시도한다.

모델의 목표 달성 요청, 마지막 인사 재생, 공급자 종료 확인이 모두 있어야
`model_reported_success`를 저장한다. 결과 요약은 모델의 보고이며 상대방 전사로 독립 검증한 기록이 아니다.

발신 전 번호 소유와 queued/ringing/in-progress 회선 부재를 확인한다.
필터 계약은 [ClawOps 공식 OpenAPI](https://api.claw-ops.com/openapi.json)의
GET calls 및 numbers 정의(2026-09-26 확인)를 따른다. 외부 프로세스와 원자적 잠금을 제공하는 API는 아니므로
같은 번호의 기존 실험 에이전트를 동시에 실행하지 않는다.

## 실제 검증 (2026-09-26)

발신 없는 점검에서 계정/발신번호, 기존 로컬 calling-agent 런타임 부재와 활성 회선 부재,
Realtime 24,000바이트 음성 생성 및 ClawOps 제어 소켓을 확인했다. 소켓 점검은 일시 연결 후 닫는다.

첫 번째 통화는 UI 직접 종료를, 두 번째는 목표 달성 요청·마지막 인사 재생 후 자동 종료를 확인했다.
두 회선은 공급자 재조회에서도 completed였다. 통화 중 채팅·새로고침 복원과 종료 후 후속 채팅도 확인했다.
두 번째 통화의 VAD 발화 구간은 4회, 재생 확인 음성은 29.85초였다. 모델이 보고한 결과를
원문 전사로 검증한 것은 아니며, 사용자는 “대화는 됐지만 음성·지연이 아쉬웠어요”라고 평가했다.

현재 숫자 계측은 DB의 비공개 metrics 필드에 남기며 원시 음성/전사를 저장하지 않는다.
VAD 종료→모델 생성→원격 재생의 구간별 지연은 아직 계측하지 않아 품질 원인을 특정할 수 없다.
같은 회선을 외부 프로세스가 동시에 사용하는 경우의 원자적 배타 제어는 제공하지 않는다.
