# 현재 기본 통화 경로: GPT-Live

2026-09-26 사용자 요청으로 기본 통화를 `gpt-live-1`로 전환했다.
기존 Azure 리소스 URL과 api-key를 재사용하고 `/openai/v1/live/sessions`로 접속한다.
`CALL_AUDIO_MODE=live`, `CALL_LIVE_MODEL=gpt-live-1`, `CALL_LIVE_VOICE=marin`을 사용한다.
기존 `CALL_REALTIME_*`의 URL·키 이름은 유지하며 자동으로 다른 제공자에게 보내지 않는다.

ClawOps G.711 μ-law 8kHz 음성과 Live를 직접 연결하며 별도 STT/TTS를 쓰지 않는다.
Live 자체 전사와 task 상태를 client delegation으로 DeepAgents에 전달한다.
`ask_user`는 채팅 확인 질문을 만들고 답을 기다린다. 실제 캘린더 조회·변경은 아직 없다.
질문 답변은 owner/call/question/revision으로 검증하며, 중복 전송은 동일 결과를 반환한다.
종료·만료·새 위임 뒤 오래된 결과는 통화에 반영하지 않는다.

화면의 전달 완료는 Live의 명령 접수 ACK이며 실제 발화·상대 청취의 증거가 아니다.
모델의 마지막 최종 답변만 전달하고 대기 해제 및 발화 지시를 함께 보낸다.
Live는 발화 완료 이벤트가 없어서 자동 종료 시 로컬 음성 활동·큐와 ClawOps 재생 ACK를
조합한다. `audio_drained`는 시간 기반 판단이며 기존 `played`와 구분해 목표 달성 확정으로
표시하지 않는다. 직접 종료는 모델 판단을 기다리지 않는다.

실제 Live·DeepAgents의 합성 음성 시험과 UI/API 자동 검증을 마쳤다.
기존 5단계의 실통화 검증을 Live 검증으로 간주하지 않는다. 실회선 ARS·음질·지연은 남아 있다.
통화 전사·질문·답변은 Git 제외 로컬 DB에 저장되며, 일반 로그에 원문을 출력하지 않는다.
첫 입력/출력/재생 시점과 위임·사용자 답변·반영 시점을 기록한다. 아직 모든 발화의 지연을
정확히 대응시키거나 종단 음질을 계측하는 기능은 아니다.

`check_live_calls.py --preflight`는 현재 설정의 모델 세션과 회선/제어 연결만 확인한다.
Live 모드에서는 음성 생성·위임까지 시험하지 않으므로 `audio_generation_tested=false`다.
`--run`은 실제 발신이므로 명시적으로 지정한 대상과 목적 안에서만 실행한다.

[6단계 구현 기록](superpowers/plans/2026-09-26-step-06-live-delegation.md).

후속 실통화에서 웹 질문·답변 접수와 Live의 답변/인사 음성 생성을 확인했다.
사용자도 실제 전화에서 답변과 마지막 인사까지 들렸다고 확인했다.
직접 종료 요청으로 마쳤으므로 실회선 자동 종료 완료 검증은 남아 있다.
새 통화의 `no_answer`, `busy`, `failed`, `canceled`는 대응하는 `call_*` 원인으로
저장·표시하며, 정상 연결 뒤 음성 오류는 `call_audio_failed`로 유지한다.
전화 요청 뒤의 별도 부정 조건을 발신 금지로 오인하던 검사도 수정했다.
[후속 수정·검증 기록](superpowers/plans/2026-09-26-step-06-call-validation.md).

6B에서 실제 통화 카드의 `통화 내용 보기`로 저장된 화자별 내역을 읽을 수 있다.
진행 중에는 기본으로 펼치며 열린 카드만 약 1초 간격으로 증분 조회한다.
접거나 탭을 숨기면 조회를 멈추고 돌아오면 이어 읽는다. 종료 뒤에도 전체 내역을 복원한다.
음성 상태는 생성/송신/재생 ACK의 통화 전체 진행 정보이며 문장별 청취 완료가 아니다.
실회선 1회에서 전사 갱신·웹 답변 반영·새로고침 복원을 확인했다.
직접 종료 없이 completed가 됐지만 `playback_unconfirmed`의 25초 대기 경로로 종료돼
업무 결과는 incomplete로 유지했다. 사용자는 답변·인사를 모두 듣고 종료됐다고 확인했다.
이 청취 확인과 시스템의 자동 판정은 구분한다. 종료 판정의 개선은 후속 과제다.
[6B 구현·검증 기록](superpowers/plans/2026-09-26-step-06b-live-transcript.md).

6C의 자동 종료는 종료 요청 이후 유효 음성을 관측하고, 마지막 유효 음성 위치까지 ACK가
도착한 뒤 양방향이 2초 이상 조용할 때 진행한다. 생성·송신 중/대기 중 음성과 부분 버퍼가
남으면 기다리며, 상대 발화가 재개되면 종료 요청을 취소한다. 무음 큐가 비기를 기다리지 않는다.
종료 요청 후 25초 상한은 유지한다. 이 시간에는 결과 발화와 인사가 포함된다.
종료 보고의 `playback`에 대기 시간·음성 목표/ACK 위치·큐/버퍼 상태를 기록한다.
Live의 `audio_drained`는 음성 활동 기반 추정으로, 문장별 청취 확정이나 `played`가 아니다.
화면은 모델 완료 보고와 재생 확인 대기 초과를 구분하고, 오류·직접 종료에는 완료 보고를 표시하지 않는다.
추가 실제 발신은 하지 않았다. [6C 구현·검증 기록](superpowers/plans/2026-09-26-step-06c-call-completion.md).

# 통화 연결

5단계 구현 완료. 모사 검증과 승인받은 본인 휴대폰 실통화 2회를 구분해 검증했다.

## 이식 출처

`../calling-agent/src/calling_agent`의 ClawOps control/connection/native,
Azure audio 세션, native_audio bridge, DTMF/end_call 계약을 필요한 범위만
`backend/src/agent_service/calls`에 이식했다. 관련 계약 테스트를 함께 옮겼다.
PCM 변환·Whisper·TTS·CLI·Journal은 가져오지 않았다. 형제 프로젝트 런타임 의존성은 없다.

G.711 μ-law 8kHz 음성을 ClawOps와 Realtime 사이에서 직접 전달한다. 서버 VAD의
끼어들기와 원격 재생 mark를 사용하며, 입력 음성 전사는 비활성화다.
음성 모델은 `send_dtmf`, `end_call`만 실행한다. 버튼 전송 성공은 메뉴 전환의 증거가 아니며,
종료 요청은 마지막 인사 재생 확인 후 서버가 회선 종료를 요청하는 동작이다.

`.env.example`의 `CALL_*`, `CLAWOPS_*`는 텍스트 모델 `MODEL_*`와 별도다.
기본적으로 통화는 비활성화이며, 발신 대상은 로컬 허용 목록으로 제한한다.
키·번호·음성 및 통화 결과는 Git에 넣지 않는다.

## 작업 수명과 복구

같은 사용자 요청 메시지는 통화 작업 하나만 만든다. DB에서 발신 시도를 먼저 기록하고
공급자 POST는 한 번만 시도한다. 공급자 idempotency key는 없으므로 응답 유실은 `unknown`으로
보존한다. 이 경우 새 발신을 막으며 운영자가 ClawOps에서 실제 회선을 확인해야 한다.

정상 종료는 회선을 정리하고, 재시작은 기존 공급자 ID의 회선만 조회·종료한다.
브라우저 종료와 채팅 중단은 별도다. 활성 상태 조회는 2초, 종료 확인은 최대 5회다.
DB 장애 직후에도 이미 얻은 공급자 ID로 직접 종료를 시도한다.

모델의 목표 달성 요청, 마지막 인사 재생, 공급자 종료 확인이 모두 있어야
`model_reported_success`를 저장한다. 결과 요약은 모델의 보고이며 상대방 전사로 독립 검증한 기록이 아니다.

발신 전 번호 소유와 queued/ringing/in-progress 회선 부재를 확인한다.
필터 계약은 [ClawOps 공식 OpenAPI](https://api.claw-ops.com/openapi.json)의
GET calls 및 numbers 정의(2026-09-26 확인)를 따른다. 외부 프로세스와 원자적 잠금을 제공하는 API는 아니므로
같은 번호의 기존 실험 에이전트를 동시에 실행하지 않는다.

## 실제 검증 (2026-09-26)

발신 없는 점검에서 계정/발신번호, 기존 로컬 calling-agent 런타임 부재와 활성 회선 부재,
Realtime 24,000바이트 음성 생성 및 ClawOps 제어 소켓을 확인했다. 소켓 점검은 일시 연결 후 닫는다.

첫 번째 통화는 UI 직접 종료를, 두 번째는 목표 달성 요청·마지막 인사 재생 후 자동 종료를 확인했다.
두 회선은 공급자 재조회에서도 completed였다. 통화 중 채팅·새로고침 복원과 종료 후 후속 채팅도 확인했다.
두 번째 통화의 VAD 발화 구간은 4회, 재생 확인 음성은 29.85초였다. 모델이 보고한 결과를
원문 전사로 검증한 것은 아니며, 사용자는 “대화는 됐지만 음성·지연이 아쉬웠어요”라고 평가했다.

현재 숫자 계측은 DB의 비공개 metrics 필드에 남기며 원시 음성/전사를 저장하지 않는다.
VAD 종료→모델 생성→원격 재생의 구간별 지연은 아직 계측하지 않아 품질 원인을 특정할 수 없다.
같은 회선을 외부 프로세스가 동시에 사용하는 경우의 원자적 배타 제어는 제공하지 않는다.
