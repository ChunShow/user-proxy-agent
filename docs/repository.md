# 저장소 범위와 업로드

현재 서비스의 Git 루트는 `agent-service/`다. 상위 작업공간 전체를 새 저장소로 만들지 않는다.
형제 디렉터리의 이전 실험·모델·참고 SDK는 이 서비스의 런타임 의존성이 아니다.

## 포함 범위

| 포함 | 로컬에 보존하고 제외 |
| --- | --- |
| 백엔드·웹 소스와 테스트 | `.env`, OAuth/모델/전화/Langfuse 인증정보 |
| 의존성 명세와 잠금 파일 | `.venv/`, `node_modules/`, 빌드·캐시 |
| 실행·검증 스크립트와 합성 입력 문장 | `data/`의 대화·토큰·암호화 키 |
| 운영 안내, 계획, 평가 결론 | `var/`의 녹음·전사·API 이벤트·평가 DB |
| 인증정보가 없는 `.env.example` | 로그, 백업, 원시 음성 파일 |
| 합성 화면을 사용한 과거 검증 이미지 | 실제 사용자 화면 캡처와 개인 데이터 |

기존 로컬 데이터·녹음·Git 이력은 보존한다. 제외 파일을 제거하는 `git clean -fdx`는
환경과 데이터까지 삭제하므로 정리 명령으로 사용하지 않는다. 백업은 [복구 안내](local-recovery.md)를 따른다.

## 최초 업로드 준비

먼저 빈 원격 저장소의 URL과 공개 범위를 정한다. 기존 로컬 이력을 유지해 올릴 수 있다.
README·license를 자동 생성한 원격과 합칠 경우 먼저 원격 이력을 확인한다.
라이선스는 아직 지정하지 않았으며 임의의 오픈소스 라이선스를 추가하지 않았다.

다음 읽기 전용 명령으로 현재 브랜치·변경·제외 대상을 검토한다.

```bash
git status --short
git branch --show-current
git remote -v
git ls-files
git check-ignore .env data/agent-service.sqlite3 data/integration.key var/
```

새 자격증명이 들어간 변경을 커밋할 때는 현재 파일뿐 아니라 공유할 이력도 확인한다.
스크린샷은 텍스트 비밀 탐지만으로 검사되지 않으므로 포함 내용을 별도로 확인한다.
현재 원격 등록이나 push는 수행하지 않았다. 목적지와 브랜치가 정해진 뒤 진행한다.

## 2026-09-27 정리 시 확인

- 정리 전 91커밋의 도달 가능한 파일 blob 734개를 조사했다.
- 현재 로컬 `.env`의 인증정보·계정값·서비스 주소와 정확히 일치하는 내용 및 점검한
  일반 비밀키 패턴은 없었다. 과거에 폐기된 모든 키나 모든 개인정보를 탐지한다는 뜻은 아니다.
- `.env`, DB, 녹음, 로그 파일이 포함된 이력 경로는 없었다.
- 검증 이미지 24개를 검토했으며 합성 채팅·번호·메일을 사용하는 개발 기록으로 유지했다.
- 추적 대상은 정리 전 약 3MB다. 약 228MB의 로컬 평가 산출물은 업로드 대상이 아니다.
