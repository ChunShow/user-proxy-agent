# 제품 방향과 구조

제품 표시 이름은 **user proxy agent**다. 장식적인 에이전트 캐릭터·슬로건보다
메시지와 통화 조작을 중심으로 한 담백한 메신저 화면을 사용한다.

## 합의한 사용자 경험

실제 사용자가 하나의 비서와 채팅하고, 비서는 요청에 맞춰 앱을 사용하거나 전화를 건다.
전화 중에도 사용자와의 채팅은 계속된다. 사용자는 통화 내용을 읽거나 듣고,
추가 조건을 전달하거나 직접 종료할 수 있다. 결과와 후속 요청은 같은 대화에 이어진다.

- 메인 에이전트와의 입력·응답은 텍스트 채팅이다.
- 채팅 흐름에 작업 상태와 통화 카드가 나타나는 웹 서비스를 먼저 만든다.
- 사용자가 말한 Meta의 muse agent와 Grok bot 채팅은 경험의 참고 대상이다.
  구체적인 화면 재현과 시각 방향은 2단계에서 실제 레퍼런스를 확인해 합의한다.
- 웹부터 반응형으로 구현하고, 이후 앱이 같은 서버 API를 사용할 수 있도록 한다.
- 시나리오는 평가에 사용한다. 실제 사용자는 자유롭게 요청하고 직접 답한다.

## 구성요소의 책임

| 구성요소 | 책임 |
| --- | --- |
| 웹 클라이언트 | 채팅, 작업·통화 상태, 실시간 내역, 음성 듣기, 추가 지시와 종료 버튼 |
| DeepAgents 메인 에이전트 | 사용자 의도·조건 파악, 앱 사용, 전화 업무 위임, 결과 판단과 후속 작업 |
| 통화 서비스 | 통화 작업의 수명 관리, 발신·종료, 음성 중계, 사용자 명령, 이벤트 기록 |
| GPT-Live 통화 에이전트 | 전화 음성 이해·응답, 업무·ARS·종료 판단을 DeepAgents에 위임 |
| 앱 연결 모듈 | 사용자별 Calendar·Gmail 연결, 허용된 조회·쓰기 도구 |
| 저장소 | 사용자 대화, 업무·통화 상태, 이벤트, 계정 연결 정보의 분리 저장 |

메인 에이전트는 전화번호, 목적, 필요한 정보, 허용 범위를 통화 서비스에 전달한다.
통화 시작은 작업 식별자를 반환하고, 진행 이벤트·결과를 비동기로 보고한다.
사용자의 추가 지시는 통화 작업에 전달하며, 종료 요청은 모델 응답을 기다리지 않고
통화 제어 경로로 전달한다. 회선 종료 확인 전에는 화면에 종료 완료를 표시하지 않는다.

3단계에서 공식 `deepagents==0.7.19`를 직접 연결했고 `langchain-openai==1.6.6`으로
설정한 텍스트 모델을 호출한다. 현재 로컬 모델은 `gpt-5.6-sol`이다.
기존 `deep-agentic` 평가 래퍼는 런타임에 사용하지 않는다. 현재 도구는 내부 계획용
`write_todos`, 전화 시작·조회·종료·추가 지시와 Google 조회·실행안 제안 도구다. 5단계에서 ClawOps와 gpt-realtime-2.1의 직접
음성 연결을 이식했다. 통화는 채팅과 독립적으로 실행하며 상태 카드·직접 종료·목표 달성 후
자동 종료를 지원한다. 새로고침·채팅 재시도·서버 재시작은 자동 재발신하지 않는다.
6단계 확장에서 기존 Azure 주소·키를 재사용하는 GPT-Live 경로를 추가하고 로컬 기본값으로 전환했다.
Live의 client delegation을 같은 모델 설정의 DeepAgents 독립 실행으로 처리한다. 일정은 사용자
채팅에 질문해 확인하며 답변을 통화에 반환한다. Google 연결이 있으면 기본 캘린더의 바쁜 시간도 조회한다.
4단계에서 대화·메시지·응답 실행 상태를 SQLite에 저장하고, 서버가 저장된 문맥으로 모델을 호출한다.
새 대화·대화 목록·전환·새로고침/서버 재시작 복원과 스트리밍·중단·재시도를 지원한다.
현재 소유권은 로컬 브라우저 세션으로 구분한다. 로그인 계정·기기 간 동기화는 아직 없으며,
쿠키 삭제/만료 뒤의 접근 복구는 지원하지 않는다. 전송 전 초안과 예시는 탭 메모리에만 둔다.

## 현재 자산과 검증 범위

- `../calling-agent/`: ClawOps ↔ Azure Realtime 직접 음성 연결, 끼어들기 처리,
  DTMF, 마지막 인사 재생 후 종료, 통화 기록·중복 발신 방지 구현.
- `../user_proxy_agent/`: 가상 사용자·상담원 및 시나리오 평가 자산. 업무별 조건과
  사용자 개입 사례를 새 서비스 평가에 활용한다.
- 새 서비스의 기본 음성 모델은 `gpt-live-1`이다. 메인 채팅 모델 선택과 별개다.
- Live 자체의 입출력 전사를 위임 문맥에 사용하고 로컬 DB에 저장한다. 원시 녹음은 저장하지 않는다.
  6B에서 통화 카드에 화자별 내역과 통화 전체의 음성 진행 표시를 추가했다.
  상태·질문·답변·결과와 함께 확인하며 접기·펼치기·새로고침 복원을 지원한다.
- DTMF는 실제 모델에 합성 ARS 음성을 입력한 시험에서 4 → 2 선택과 메시지 생성을 확인했다.
  병원 실회선에서는 휴일 안내로 해당 메뉴를 진행하지 못했다. 실회선 메뉴 전환 검증은 남아 있다.
- 병원 실제 통화에서 마지막 인사 뒤 자동 종료를 확인했다. 일반 진료 시간 확인 목표는 미달성했다.

## 제품 동작 원칙

- 업무 상태와 통화 상태는 별도로 관리한다. 통화가 정상 종료되어도 업무가 미완료일 수 있다.
- 화면용 전사는 수정 가능성이 있는 부분 결과와 확정 결과를 구분한다.
  에이전트의 생성 내용과 실제 재생된 내용도 구분한다.
- 전화 듣기 끄기는 브라우저 청취만 멈추며, 실제 통화 종료와 구분한다.
- 사용자 채팅은 에이전트에게 주는 지시다. 전화 상대에게 그대로 읽을 발화와 구분한다.
- 이미 위임된 범위는 진행하고 새 결정이 필요하면 사용자에게 질문한다.
- 계정 연결과 사용자 데이터의 소유권은 서버에서 확인한다. 키·토큰을 브라우저에 전달하지 않는다.
- 화면 재연결은 기존 작업 상태를 복원한다. 재연결이나 서버 재시작을 재발신 명령으로 취급하지 않는다.
- 사용자가 마이크로 통화에 직접 참여하거나 통화를 넘겨받는 기능은 후속 설계 대상이다.

## 초기 기술 구성 제안

1단계 계획의 컨펌 대상: Python 3.12 이상·uv·FastAPI 백엔드, React·TypeScript·Vite 웹.
의존성의 구체적인 버전은 구현 시 호환성을 확인한 후 lockfile로 고정한다.
초기에는 한 프로젝트 안에 웹과 서버를 두고, 통화 서비스는 책임을 분리한 모듈로 시작한다.
프로세스 분리가 필요하면 5단계 계획에서 작업 수명·장애 처리를 근거로 결정한다.

처음부터 모바일에서 사용할 공통 HTTP·스트리밍 인터페이스를 설계하되,
네이티브 앱·음성 사용자 입력·다중 회선은 현재 12단계 로드맵의 구현 범위에 포함하지 않는다.

## 5단계 검증과 품질 과제

본인 전화 2회에서 UI 발신·동시 채팅·새로고침·직접 종료 및 음성 모델의 목표 달성 요청 후
자동 종료를 확인했다. 통화 결과 요약은 모델의 보고이며 상대방 전사로 독립 검증하지 않았다.
사용자는 대화가 됐지만 음성·지연이 아쉽다고 평가했다. 음성 자연스러움과 응답 지연 개선은
남아 있으며, 구간별 지연 계측을 포함한 별도 계획과 확인 후 진행한다.

## GPT-Live 검증과 제한

실제 Live·DeepAgents에 합성 예약 문의를 입력해 채팅 질문 생성, 시험 답변 수신,
“3시 불가·4시 가능”의 음성 반환을 확인했다. 시험 답변은 자동 입력했으며 사용자 실통화가 아니다.
사용자 답변은 해당 질문 ID와 revision에 연결하고 종료·만료·조건 변경 뒤의 오래된 결과는 폐기한다.
Live는 발화 완료 이벤트가 없으므로 자동 종료는 음성 활동·큐·ClawOps 재생 확인으로 판단한다.
정확한 마지막 인사 완료를 증명할 수 없으면 목표 달성으로 확정 표시하지 않는다.
이 문단은 6단계 당시 기록이다. 브라우저 듣기와 Google 연결 코드는 이후 추가했고, 실제 계정 연결·청취·Live 실회선 ARS·음질·지연 검증은 남아 있다.

6A 후속 실통화에서는 웹 질문에 접수된 답변이 Live에 반영되고, 그 답변과 마지막 인사의
음성이 생성되는 것을 확인했다. 마지막 인사 재생 대기 중 직접 종료 요청을 받았으므로
해당 시험으로 자동 종료 완료를 입증하지 않는다. 발신 요청의 부정어 오탐을 수정했고,
새 통화부터 부재중·상대 통화 중·회선 실패·취소를 음성 연결 오류와 구분해 표시한다.
사용자는 실제 전화에서 답변과 마지막 인사까지 들렸다고 확인했다.

6B 실회선 시험에서는 통화 중 전사가 화면에 갱신되고, 웹의 가상 답변이 Live 출력에 반영된 후
종료된 기록이 복원되는 것을 확인했다. 전사 표시 구간은 읽기 위한 구분이며 발화 확정 이벤트가 아니다.
음성 생성·전송·재생 ACK를 구분하며 문장별 청취 완료를 표시하지 않는다.
직접 종료 요청 없이 회선이 종료됐지만 재생 완료 판정은 실패해 25초 대기 후 종료됐다.
사용자는 답변과 마지막 인사를 모두 듣고 그 뒤 종료됐다고 확인했다.
종료 타이밍 개선과 성공/미확인 결과 표현은 별도 검증·수정 과제다.


6C에서는 마지막 유효 음성 끝까지의 재생 ACK와 양방향 음성 활동을 기준으로 종료하도록 개선했다.
계속 생성되는 무음 때문에 전체 송신량을 따라잡지 못하는 문제를 피하고,
아직 송신 중·대기 중인 음성과 부분 버퍼, 상대의 새 발화가 있으면 조기 종료하지 않는다.
25초는 종료 요청 시점부터의 최종 대기 상한이며 결과 설명과 인사 시간도 포함한다.
화면은 모델의 업무 완료 보고와 재생 확인 부족을 구분하며 Live의 추정 결과를 확정 성공으로 바꾸지 않는다.
자동 검사는 통과했다. 이후 승인된 실제 통화 1회에서는 인사 뒤 추가 상대 발화가 있었고
통화가 유지되어 사용자가 직접 종료했다. 최종 종료 보고가 비어 있어 자동 종료 성공을 확인하지 못했다.
종료 요청·취소 이력과 상대의 추가 발화 후 재판단 흐름은 후속 개선 과제다.

## 8단계 구현과 검증 범위

메인 채팅에서 현재 대화의 연결된 Live 통화에 추가 조건을 전달할 수 있다.
서버가 사용자·대화·메시지의 소유권을 확인하고 중복 접수와 동시 전달을 제한한다.
새 조건은 이전의 진행 중 위임·질문을 무효화하며, 취소된 답변과 늦은 도구 결과는 적용하지 않는다.
전달 완료된 추가 조건은 다음 업무 판단에도 유지한다. 이미 발화한 음성은 소급 취소하지 않는다.

통화 카드의 전달 상태는 저장·복원되며 모델 명령의 수신 확인과 상대방 청취·업무 완료를 구분한다.
ACK 누락·연결 종료·서버 재시작으로 수신 여부가 불명확하면 자동으로 재전송하지 않는다.
모사 통합 검사 후 승인된 본인 번호 1회 실통화에서 웹의 시간 조건 변경이 Live 질문에 반영되고
실제 음성으로 들리는 것을 확인했다. 직접 종료와 새로고침 후 전달 기록 복원도 확인했다.
이미 발화한 조건의 정정과 실행 중 위임의 경합은 이번 실회선 시험 범위에 포함하지 않았다.
당시 보류했던 브라우저 듣기·자동 종료 후속 개선은 이후 2026-09-27 자율 작업에 포함했다.

## 2026-09-27 개인용 로컬 기능

Google OAuth 연결/해제와 권한별 Calendar/Gmail 조회, 일정 등록·메일 발송 확인 카드를 구현했다.
이후 본인 계정의 실제 로그인·조회/쓰기 권한 동의를 완료했다. 웹에서 빈 일정 조회와 최근 메일
5개 요약, 응답 완료와 새로고침 복원을 확인했다. 이후 웹 확인 카드로 테스트 일정 1건 등록과
본인 메일 1건 발송·수신을 실제 Google 결과로 검증했다. 토큰은 로컬 암호화 저장이고
키는 Git 제외 파일이다. 실행안은 30분 만료, 계정 고정, 명시적 웹 실행, 재시작/응답 유실 시 자동 재전송 없음.
전화 위임은 기본 캘린더의 바쁜 구간만 받는다. 빈 일정은 예약 동의나 완료가 아니다.

통화 듣기는 세션/Origin/owner 검사 후 메모리 음성을 브라우저에 전달하며 통화 제어와 독립이다.
Live 종료 취소 이력을 남기고 새 전사·무음 조건에서 종료 여부를 제한적으로 재판단한다.
새 발화와 사용자 조건을 우선하며 질문 대기 중에는 별도의 판단을 시작하지 않는다.
통화 듣기·종료 재판단은 자동/모사 검사로 검증했고 새 실회선 검증은 남겨 두었다.
공개 배포, 다중 사용자 로그인, 네이티브 앱, 사용자의 마이크 통화 참여는 이번 범위에 포함하지 않는다.

## 로컬 실행 추적

메인 DeepAgents 채팅과 통화 위임·종료 보조 판단에 선택적 Langfuse 추적을 연결했다.
모델/도구 이름, 시간, 반환·오류·취소 상태와 원 요청의 관계만 수집한다. 원문 입력/출력,
전사, 전화번호·이메일·인증정보는 수집하지 않는다. 같은 사용자 요청은 같은 trace로 묶인다.
통화 종료 요청·인사 명령 ACK·재생 판정·회선 종료 단계도 메타데이터로 추적한다.
음성 패킷과 웹 확인 카드의 실제 Google 쓰기 실행은 이 추적 범위 밖이다.
기존 SQLite 업무 기록은 계속 유지하며 수집 서버 장애는 채팅·통화를 중단시키지 않는다.

종료 시 Sol은 내부 결과 요약과 상대에게 말할 내용을 구분한다. 필요한 안내와 인사가 이미
전달됐다면 재발화 없이 기존 음성 재생을 확인하고, 남은 정보가 있으면 그 정보와 인사를
한 번의 발화로 요청한다. 모사 및 실제 Sol 합성 전사로 검증했다. 후속 본인 통화 1회에서는
전사상 인사 1회, 종료 요청부터 7.2초에 재생 조건 충족, 이후 회선 종료를 확인했다. 사용자도 인사 한 번 후
자동 종료됐다고 확인했다. 이미 인사한 분기는 이번 실회선에서 선택되지 않았다. 후속 개선으로 요약을
종료 요청 시점의 기록으로 표시하고, 새 모델 요약에는 확인된 업무 답변·미해결 사항만 담도록 했다.
종료 안내는 음성 전송·무음 확인과 실제 청취 미확인을 구분한다. 과거 본문은 보존하며
Live의 재생 추정 한계는 남아 있다.


메인 채팅의 통화 결과 조회도 종료 요청 시점 요약·회선 상태·종료 근거·최근 자동 전사를
함께 사용한다. 전사는 최대 80개/12000자이며 잘림 여부와 청취 미확인을 명시한다.
과거 요약에 인사 전 메모가 남아도 이후 전사를 조회해 설명한다. 실제 웹 결과 질문에서
조회 도구 호출과 인사 기록·종료 상태 설명을 확인했다. 원문 전사는 Langfuse에 수집하지 않는다.

자동으로 전달하는 통화 문맥에는 기록 목록·상태·결과 존재 여부만 넣고, 요약 본문과 전사는
상세 조회에서 제공한다. 통화 결과를 일정·메일 확인 대기 실행안으로 옮기는 흐름은 실제 Sol과
합성 기록으로 검증했다. 조회만 요청하거나 시간이 불명확하면 실행안을 만들지 않는 사례도
확인했으며, 실제 Google 후속 실행까지 이어지는 전체 실사용 검증은 남아 있다.


통화가 새로 종료·실패·취소되면 원래 채팅에 결과가 자동으로 한 번 추가된다. 현재 메인 모델이
저장된 근거만 읽어 도구 없이 요약하며 회선 종료는 요약을 기다리지 않는다. 오류·생성 중 재시작은
고정 안내로 복구한다. 작성 중 초안·일반 응답·재시도·이전 메시지를 보존하고 과거 통화는 소급
보고하지 않는다. 합성 통화/실제 텍스트 모델/브라우저로 검증했으며 새 실회선 검증은 남아 있다.
