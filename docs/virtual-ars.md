# 같은 웹에서 가상 ARS 디버깅

좌측 하단 **디버깅**을 누르면 가상 ARS 전용 새 대화를 만든다. 일반 **새 대화**는 기존
ClawOps 통화 모드다. 별도 웹 주소로 이동하지 않으며 기존 공유 주소에서도 같은 기능을 쓴다.

가상 ARS 자체는 독립 로컬 HTTP/WebSocket API다. 별도 외부 API 가입이나 키 발급은 필요 없다.
안내 음성은 macOS에서 생성한다. 기존 Live-1과 메인 모델 API 호출 비용만 발생한다.

## 실행

[README](../README.md)의 개발 환경 설치 후 저장소 루트에서 실행한다.

```bash
./scripts/dev.sh
```

- 기존 웹: http://127.0.0.1:5180 — 좌측 하단 **디버깅**
- 기존 백엔드: http://127.0.0.1:9010
- 내부 ARS API: http://127.0.0.1:9020/health
- 종료: 실행 터미널에서 Ctrl-C. 실행기가 시작한 세 프로세스를 함께 종료한다.

macOS `say`/`afconvert`와 설치된 한국어 `Yuna` 음성을 사용한다. 첫 실행 때 생성한 안내는
`var/simulator/audio/`에 캐시한다. 내부 API 키는 `var/simulator/api-token`에 0600 권한으로
자동 생성한다. 기존 `.env`의 메인 모델과 `CALL_REALTIME_*` 설정을 그대로 사용한다.
가상 통화에는 ClawOps 계정·발신번호가 필요 없다.

가상 서버를 실행하지 않을 환경에서는 `VIRTUAL_ARS_ENABLED=0 ./scripts/dev.sh`로 시작한다.
이때 일반 기능은 그대로 사용할 수 있고, 가상 서버 연결 실패가 실제 발신으로 전환되지는 않는다.
기존 `scripts/dev_simulator.py`도 이제 같은 통합 실행기를 호출한다. 5181/9011 서버는 사용하지 않는다.

## 사용

1. 사이드바 하단 **디버깅**을 누른다. 모바일에서는 왼쪽 위 메뉴를 먼저 연다.
2. 상단 **가상 통화 · 실제 전화 발신 없음**을 확인한다.
3. 아래처럼 요청하고 **승인하고 가상 통화 시작**을 누른다.

> 01000000001 가상 병원 ARS에 전화해서 진료시간과 점심시간, 주말 진료 여부를 확인해줘.
> 안내를 먼저 듣고 필요한 버튼을 눌러서 확인되면 종료해줘.

같은 대화에서 전사·양쪽 음성 듣기·추가 지시·직접 종료·결과 보고를 사용할 수 있다.
첫 메시지 이후 저장된 대화는 새로고침·이전 대화 열기·서버 재시작에도 모드를 유지한다.
이전 대화 목록과 통화 카드에도 **가상 통화/가상 ARS** 표시가 남는다.

현재 시험 번호는 **01000000001** 하나다. `4(기타 안내) → 2(진료 시간)`을 누르면
평일 09:00–18:00, 점심 12:00–13:00, 주말·공휴일 휴진을 안내한다.
**모두 가상 데이터이며 실제 병원 정보가 아니다.** 등록되지 않은 번호는 거부한다.
무입력은 20초 대기 후 두 번 재안내하고 종료한다. 전체 회선 제한은 180초다.

## 분리 경계

- 서버 DB의 `conversations.mode`를 통화의 `phone_calls.mode`로 복사해 저장한다.
  생성 후 모드를 바꾸는 API는 없으며 모델의 입력이나 브라우저 표시로 공급자를 바꾸지 않는다.
- 가상 모드는 승인·실행·복구·종료 모두 `SimulatorGateway`를 사용한다. ClawOps fallback은 없다.
- 같은 소유자의 대화 목록과 DB를 공유한다. 디버깅 대화에서는 Google 조회·쓰기 도구를 제외한다.
- 일반 대화에서 생성된 실제 발신 카드에도 기존 사용자 승인 절차를 유지한다.
- 서비스 전체 통화는 기존처럼 한 번에 한 개다. 다른 대화에서 통화 중이면 기존 통화를 안내한다.
- 과거 별도 시험의 `var/simulator/debug.sqlite3`는 보존하지만 자동으로 합치지 않는다.
- 기존 공유 주소만 사용하며 ARS API를 인터넷에 직접 노출하지 않는다.

## API

`GET /health`를 제외한 REST와 WebSocket에는
`Authorization: Bearer <var/simulator/api-token의 값>` 헤더가 필요하다.
키를 브라우저 코드나 커밋, 공유 URL에 넣지 않는다.

| 메서드 | 경로 | 내용 |
| --- | --- | --- |
| GET | `/health` | 준비 상태, `real_calls=false` |
| GET | `/scenarios` | 시나리오와 가상 번호 |
| POST | `/calls` | `{ "request_id": "UUID", "destination": "01000000001" }` |
| GET | `/calls/{id}` | 메뉴·입력·재생·종료 증거 |
| POST | `/calls/{id}/hangup` | 가상 회선 종료 |
| WS | `/calls/{id}/media` | 양방향 G.711 μ-law, 8kHz mono |

동일 `request_id`는 같은 회선을 반환한다. 통화 ID는 `SIM` 접두사다.
회선당 미디어 연결은 하나만 허용하며, 재접속/재발신은 자동으로 하지 않는다.

서버는 `start`, 20ms/160바이트 `media`, `mark`, `stop` 이벤트를 보낸다.
클라이언트는 다음 형식으로 오디오·버튼·재생 제어를 전달한다.

```json
{"event":"media","media":{"payload":"BASE64_MULAW"}}
{"event":"dtmf","dtmf":{"digit":"4"}}
{"event":"mark","mark":{"name":"playback-1"}}
{"event":"clear"}
```

`mark`는 앞선 오디오의 실제 시간 길이만큼 대기한 후 반환한다. `clear`는 대기 오디오와
미확인 mark를 폐기한다. 재생량은 무음을 포함한 μ-law 바이트 수이며 사람이 들었다는 증거는 아니다.

조회 결과의 `digits`는 실제 수신한 DTMF, `stage`는 메뉴 상태,
`hours_delivered`는 진료 안내가 끝까지 전송됐는지 나타낸다. `events`에는 상대 시간과
선택·안내 재생·종료 이유가 남는다. 이 회선 기록은 메모리에 최대 100개,
각 300개 이벤트로 제한한다. 재시작하면 사라진다. 앱의 전사·활동 기록은 기존 서비스 DB에 대화별로 남는다.

## 검증과 범위

자동 검사는 인증, 번호 거부, 중복 생성, 메뉴 선택, 잘못된 입력, 무입력 종료,
단일 WS 연결, 실제 시간 mark ACK, clear, 직접 종료와 ClawOps 미사용을 검사한다.
실제 Live-1 검증은 [초기 회선](superpowers/plans/2026-09-28-virtual-ars.md)과
[통합 디버깅 대화](superpowers/plans/2026-09-28-conversation-debug-mode.md) 기록을 참고한다.

이는 통신망 품질이나 실제 병원 응대의 검증이 아니다. 현재 가상 상대는 고정 음성 ARS이며
자유 대화 상담원, 여러 기관으로의 재발신, 잡음·회선 지연·끊김 시나리오는 후속 확장이다.
