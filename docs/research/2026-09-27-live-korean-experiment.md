# 전화 없는 한국어 Live 비교 — 1차 결과

2026-09-27. 실제 GPT-Live API와 합성 음성으로 비교했으며 실제 전화는 걸지 않았다.
이번 결과는 대화 정책 개선과 재현 가능한 계측을 제공한다. 한국어 자연스러움 전체가
해결됐거나 특정 음성이 가장 좋다는 결론은 아니다.

## 방법

- 기존 endpoint/key, gpt-live-1, PCMU 8kHz. macOS Yuna 175wpm 고정 합성 입력.
- 날짜/시간 읽기와 준비물 질문, 발화 중 오후 시간으로 정정, 짧은 맞장구, 일반 대화.
- 기준 지시와 개선 지시, marin/gleam/meridian을 실제 API에 전달.
- 기존 LiveBridge의 receive/phone/play를 실행하되 회선은 메모리 객체, ACK는 모사.
  종료 판단/Google/실제 Sol 위임 경로는 이 음성 실험에 연결하지 않는다.
- 실제 통화 요청/운영 DB 기록/메일·일정 변경 없음. 세션 길이 32~42초.
- 세션 개설 총 12회 중 유효 음성 실행 9회. 앞선 실험 도구의 append 이벤트에서
  필수 delegation_id:null을 빠뜨려 3회가 무효였다. 이들은 품질 비교에서 제외했다.
  재현 스크립트는 수신 작업 오류 즉시 종료와 제한 시간, 음성 없음 실패를 처리한다.

## 결과

정정 입력 시작부터 300ms 이상 연속 저음량이 시작될 때까지의 모사 재생 시간이다.
이는 의미 있는 양보의 확정 판정이 아니며 자연스러운 쉼도 포함할 수 있다.
모델 수신 청크를 20ms로 나눠 회선 패킷과 같은 해상도로 측정한다.
네트워크 수신 공백 자체를 무음으로 계산하지 않는다.

| 조건 | 모사 재생의 저음량 시작 | 정정 입력 중 출력 발성 합계 |
| --- | ---: | ---: |
| 기존 marin, 첫 비교 | 2,362ms | 1,862ms |
| 개선 marin, 첫 비교 | 933ms | 1,973ms |
| 기존 marin, 발성 중 재검증 | 1,476ms | 3,516ms |
| 개선 marin, 발성 중 재검증 | 1,330ms | 2,383ms |
| 개선 gleam | 2,425ms | 2,205ms |
| 개선 meridian | 2,629ms | 2,397ms |

기존 marin 추가 1회에서는 삽입 시점이 문장 사이 쉼과 겹쳐 2ms가 나왔다.
이 수치는 응답 정지 성능으로 해석하지 않는다. 이후 실행은 중계가 실제 발성 중일 때만
정정/맞장구를 삽입하도록 보완했다. 입력 파일 자체의 초기 무음도 포함되므로
발음의 시작점부터 잰 수치는 아니다. 반복 수가 적고 확률적 모델이므로 통계적 우열은 미확정이다.

모든 정정 사례의 자동 전사에서 바뀐 오후 시간이 반영됐다. 개선 지시의 한 실행에서는
요청보다 추가 설명을 덧붙였다. 개선 marin은 맞장구 뒤 원래 안내를 이어갔으며
일반 문답에서도 날짜·시간과 두 준비물을 전달했다. 전사만으로 발음의 자연스러움을 평가하지 않았다.

9개 유효 실행 모두 중계로 보낸 바이트는 모델 원본의 같은 접두 부분과 일치했다.
종료 시점의 미전송 꼬리는 별도로 보존되며 전체 출력 완료를 뜻하지 않는다.
최대 생성-전송 대기는 200~300ms였다. 실제 회선 전송/재생 지연은 이 수치에 포함되지 않는다.
일부 모사 재생에서 인접 발성 패킷 사이 공급 공백 44/99/103ms를 관측했다.
다른 실행에서는 없었으며 이 현상만으로 사용자가 경험한 끊김의 원인을 확정할 수 없다.
일괄 출력 큐 삭제나 입력 음량만을 기준으로 한 강제 음소거는 추가하지 않았다.

## 적용

- 차분한 일상 존댓말, 짧은 문장, 문장 내 연결과 날짜/시간 읽기 예시.
- 명시적 Interruption/Backchannel/Delegation 정책. 정정 시 듣기, 짧은 맞장구와 취소 구분.
- 반복 대기 멘트와 결과·인사 반복 억제. 기존 권한/위임/종료 통제 유지.
- 기본 음성은 marin 유지. CALL_LIVE_VOICE에 gleam/meridian도 선택 가능.
  세션 시작 응답이 요청한 음성과 일치하는지 검증한다.
- 프롬프트는 위의 개선 비교 고정본과 동일하다. 중계 큐/강제 clear는 변경하지 않았다.
- 관련 회귀 58개 및 backend/scripts Ruff 통과. 활성 통화/채팅 실행 0건 확인 후
  backend 재시작, health 정상 확인. 추가 발신 없이 이후 세션에 적용된다.

## 샘플과 재현

`scripts/check_live_korean.py`의 --prepare와 --run은 README의 실행법을 따른다.
합성 파일/개별 JSON/원본 WAV는 ignored `var/korean-live-lab/`에 있다.
이번 비교 페이지는 `var/korean-live-lab/index.html`, HTTP 127.0.0.1:9122에서 제공한다.
입력+모사 재생 합성 WAV와 모델 단독 WAV를 각각 들을 수 있다.

현재 도구에서 출력 음성을 직접 청취할 수 없어 억양·음색의 주관 평가를 수행하지 않았다.
음성 선호는 사용자 청취로 확인하며 선택 전에는 marin을 유지한다. 후속으로 실제 사람 음성,
잡음/에코, 서로 다른 말속도·한국어 화자, 실제 회선의 공급 공백을 별도로 확인해야 한다.
이번 단계만으로 중간 음절 잘림이 완전히 해결됐다고 보고하지 않는다.

## 사용자 청취 피드백

비교 페이지 제공 후 사용자가 “개선 지시 · marin · 1 이거 괜찮은 거 같아”라고 답했다.
해당 샘플의 개선 지시와 현재 제품 INSTRUCTIONS가 일치하고 실제 설정이 live/marin임을
확인했다. 이 조합을 기본값으로 유지한다. 이 피드백은 선택한 샘플에 대한 긍정 평가이며,
모든 대화의 자연스러움이나 실회선 끊김 해소를 확인한 것으로 확대하지 않는다.
