# 저장소 업로드 전 작업공간 정리

상태: completed

승인 범위: 사용자가 “현재까지 작업물을 깃레포에 올리려고 해. 올리기 전에 작업공간을
정리하고 싶어.”라고 요청했다. 기존 기능의 변경 없이 업로드 준비를 위한 문서·제외 규칙과
Git 대상을 정리한다. 현재 서비스의 독립 저장소인 `agent-service`가 기본 대상이다.
범위 질문에 사용자가 “agent-service만 정리 (권장)”을 선택해 이를 확인했다.

## 범위와 완료 기준

1. 추적 파일과 기존 Git 이력을 점검한다. 현재 로컬 자격증명과 일치하는 값, 일반적인
   비밀키 패턴, 데이터/녹음 파일의 포함 여부를 값 자체를 출력하지 않고 확인한다.
2. README를 현재 제품·설치·실행 중심으로 정리한다. 설정/평가 안내를 별도 문서로 옮기고
   삭제된 화면 예시 및 오래된 검증 개수·미구현 안내를 바로잡는다.
3. 로컬 DB·인증정보·녹음의 예외 위치도 Git 제외 규칙에 추가한다. 기존 데이터와 개발 서버,
   이전 실험 프로젝트, 평가 원본과 Git 이력을 보존한다.
4. 문서 링크, 변경된 제외 규칙, 신규 추적 파일을 확인하고 로컬 커밋한다.
   동작 코드 변경이 없으므로 제품 전체 테스트나 실제 API/전화 시험은 반복하지 않는다.

원격 주소·공개 범위는 아직 정해지지 않았다. 이번 작업은 로컬 정리까지이며 저장소 생성,
push, 이력 재작성과 파일 영구 삭제는 포함하지 않는다.

## 조사 결과

- 시작 시 작업 트리 clean, 원격 없음, 91커밋, 추적 파일 253개/약 3MB.
- 도달 가능한 이력의 blob 734개에서 현재 `.env`의 키·계정값·서비스 주소와 일치하는 내용
  및 점검한 일반 비밀키 패턴이 없었다. 모든 종류의 비밀 탐지를 보장하는 검사는 아니다.
- `.env`, DB, 녹음, 로그가 추적된 이력 경로는 없었다.
- 기존 검증 스크린샷 24개를 모아 검토했다. 합성 시험 화면을 개발 기록으로 보존한다.
- 약 228MB의 평가/로그와 사용자 DB는 이미 Git 제외 상태이므로 삭제할 이유가 없다.

## 완료 내용과 검증

- README를 현재 기능·설치·실행 중심으로 줄이고 설정 안내와 스크립트 사용법을 분리했다.
  삭제된 화면 예시와 휴지통 복원 UI 안내, 오래된 설치/검증 상태를 바로잡았다.
- Git 제외에 DB 복사본·인증 파일·원시 음성·백업을 추가했다. 소스·기존 픽스처가 새 규칙에
  잘못 제외되지 않는지, 대표적인 제외 경로 19개가 모두 적용되는지 확인했다.
- Markdown 로컬 링크 89개가 모두 유효하고, staged 트리 258개 파일(약 3MB)에
  현재 알려진 키나 실행 데이터 디렉터리가 없는 것을 확인했다. 기존 24개 합성 검증 이미지는
  과거 기록임을 명시했다.
- 제품 코드·의존성·개인 `.env`·DB·음성 원본은 변경하지 않았다. API 호출/전화/Google 실행 없음.
- 원격 주소·공개 범위·업로드 브랜치는 미정이다. 이력 재작성 없이 현재 로컬 이력을 유지한다.
