## 순서와 완료 기준

1. 실제 웹 새 대화에서 두 실행안을 요청한다.
2. 생성된 카드의 계정·시간·수신자·제목·본문이 승인된 시험 범위와 일치하는지 검토한다.
3. 사용자가 위임한 시험 조작으로 웹 확인 버튼을 각 1회 누른다. 채팅 모델은 제안만 한다.
4. succeeded와 실제 Google 일정/메일 존재·내용을 확인한다. unknown이면 다시 실행하지 않고
   먼저 공급자에서 결과를 조회한다.
5. 새로고침 후 성공 상태 복원과 중복 실행 버튼 제거를 확인한다.

## 실제 검증 결과

- 웹의 새 대화에서 메인 에이전트가 일정·메일 실행안을 각각 1건 생성하고 미실행 상태로 안내했다.

- 확인 카드의 계정·수신자·시간·제목·본문을 검토한 후 웹 버튼을 각각 1회 실행했다.
  두 로컬 실행 결과 모두 `succeeded`이며 Google 공급자 ID가 저장됐다.

  confirmed 상태, 참석자·반복 없음까지 확인했다.
- Gmail의 제목·본문·유일한 수신자가 실행안과 일치했다. `SENT`와 `INBOX` 라벨을 확인해

- 새로고침 후 두 완료 카드와 Google 확인 문구가 복원됐고 실행 버튼이 사라졌다.
