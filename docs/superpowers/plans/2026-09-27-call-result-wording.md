# 종료 결과의 시점과 확인 범위 표시

상태: completed

## 승인과 원인

직전 실제 통화 검증에서 인사 전 판단 문장이 최종 결과처럼 남는 표시 문제를 보고했다.
사용자가 “후속 개선 진행해줘/”라고 해당 개선을 승인했다.
end_call.summary는 인사 전에 생성되고 manager._finish가 그대로 reported_summary로 저장한다.
웹은 이를 '통화 도우미가 정리한 결과'로 표시해 이후 회선 종료 상태와 혼동시켰다.

## 범위·작업 단위

1. 기존 기록을 덮어쓰지 않고 요약의 작성 시점을 명시한다. 기존 담백한 통화 카드 디자인과
   글자·간격을 유지하고 라벨·안내 문구만 조정한다.
2. Live의 end_call 요약 지침은 확인된 업무 답변·미해결 사항만 포함하도록 명시한다.
   인사 전/후 상태, 종료 예정 등 제어 메모는 요약에 포함하지 않도록 한다.
3. audio_drained의 종료 안내는 마지막 음성 전송·무음 확인과 실제 청취 여부를 구분한다.
   업무 목표 달성 여부와 재생/회선 상태를 분리하고 실패·직접 종료·미확인 상태는 유지한다.
4. 결과 분기 회귀 검사, 타입·정적 검사·빌드, 실제 Sol 합성 입력 및 웹 기존 기록 복원으로 확인한다.
   실제 발신·Google 조회/쓰기·기존 전사 변경은 없다.

## 파일·완료 기준

- backend/src/agent_service/calls/delegation.py: 요약 지침.
- web/src/chat/callResult.ts, callResult.test.ts, PhoneCallCard.tsx: 결과 안내와 시점 라벨.
- docs/product.md, docs/roadmap.md 및 이 문서: 검증·제한 기록.

기존 통화 기록에 시점 라벨이 보이고, 자동 종료와 청취 미확인의 차이가 드러나야 한다.
새 요약 정책은 합성 입력으로 실제 모델에 확인한다. 모델 지침은 확률적이며 실제 통화 검증과
동일시하지 않는다. 이미 인사한 분기의 실회선 검증은 이 작업에 포함하지 않는다.

## 결과·검증

- 요약 라벨을 '종료 요청 시점의 요약'으로 변경했다. 기존 기록은 보존하며 이후 종료 상태와
  구분한다. 새 Live 요약 지침에는 업무 답변·미해결 사항만 남기고 인사·회선 제어 메모를 제외했다.
- audio_drained는 마지막 음성 전송·무음 확인 후 종료와 실제 청취 미확인을 구분한다.
  목표 달성/거절/진행 불가 각각의 업무 판단과 재생 상태를 별도로 설명한다.
  실패·직접 종료·미확인 데이터에서 성공으로 표시하지 않는 기존 보호는 유지한다.
- 결과 분기 테스트 3개 실패를 먼저 확인한 후 수정했다. 웹 단위 테스트 28개 통과,
  관련 backend 위임 테스트 14개 통과, TypeScript·ESLint·Ruff·웹 빌드 통과.
  최종 reason 타입 가드 보강 뒤 관련 5개 테스트와 TypeScript를 다시 통과했다.
- 실제 Sol 모델 + DelegationCoordinator/end_call 도구, 임시 DB와 모사 bridge에 합성 전사
  2개를 넣었다. 인사 전·인사 후 모두 요약은 통화 가능 여부만 포함했고, 인사 후 사례는
  farewell_already_said=true와 기존 재발화 방지 경로를 유지했다. 실회선 시험은 아니다.
- 실제 웹의 기존 통화에서 새 시점 라벨·종료 안내를 확인하고 스크린샷으로 가독성을 확인했다.
  활성 통화·응답 0건에서 backend를 재시작하고 웹 새로고침 후 기록 복원을 확인했다.
- E2E 기대 문구도 맞춰 갱신했다. 이번에는 자동 브라우저 E2E 전체를 실행하지 않았으며,
  실제 브라우저 확인과 단위 검사로 검증했다. 추가 발신·Google 작업은 없었다.

## 남은 제한

과거 요약 본문은 당시 모델 기록으로 남는다. 새 요약 정책은 모델 지침이므로 모든 답변의
형식을 보장하지 않는다. Live의 음성 재생 확인은 추정이며 실제 청취를 자동 판정하지 않는다.
이미 인사한 경로의 추가 실회선 검증은 별도 승인 시 진행한다.

## 메인 채팅 후속 검증·수정

사용자는 위 개선 완료 보고 후 “진행해줘.”라고 요청했다. 결과 설명의 후속 검증으로
같은 웹 대화에 기록 조회만 요청했으며, 모델이 과거 요약의 인사 미전달 문장을 반복하고
종료 경위는 알 수 없다고 응답하는 문제를 재현했다. 통화 카드 개선과 같은 결과 해석 문제의
남은 경로를 수정한다. 상태: completed.

- 원인: call_history는 종료 시점/재생 근거를 제외한 과거 요약만 제공하고, get_phone_call도
  별도로 저장된 자동 전사를 제공하지 않는다. 메인 모델이 상세 조회 없이 요약을 재사용했다.
- calls/tools.py와 chat/runtime.py: 요약 시점·종료 근거를 문맥에 포함하고, 자세한 결과 질문은
  get_phone_call로 조회하도록 지시한다. 자동 전사는 실제 청취 증명으로 취급하지 않는다.
- calls/live_store.py: 소유권 검사 후 최근 자동 전사 최대 80개/12000자와 잘림 여부를 조회한다.
  기존 데이터는 바꾸지 않는다. tool 조회에만 제공하며 Langfuse 원문 수집 정책은 유지한다.
- tests/calls/test_agent_tools.py: 과거 요약·새 전사·종료 근거 동시 제공, 소유권 거절,
  긴 전사 잘림과 부정확한 종료 기록의 안전한 처리를 검사한다.
- 실제 웹에서 동일 질문을 재검증한다. 새 발신·메일·일정 변경은 실행하지 않는다.

### 메인 채팅 수정 결과

- get_phone_call은 기존 결과에 summary_timing, 정규화된 end_evidence와 최근 자동 전사를
  추가한다. 전사는 모델 delta임을 명시하고 청취 확인 false 및 잘림 여부를 전달한다.
  소유권 검사 후 최대 80개/12000자를 반환하며 다른 사용자·다른 종류 이벤트는 노출하지 않는다.
- call_history에도 종료 근거·요약 시점을 포함한다. 메인 지침은 상세 결과 질문에서 조회 도구를
  사용하고, 과거 요약의 제어 메모나 incomplete만으로 인사 미전달을 단정하지 않도록 한다.
- 새 회귀 6개가 기존 구현에서 실패하는 것을 확인한 후 수정했다. 관련 도구·기록·관측성
  테스트 25개 통과, Ruff 및 git diff --check 통과. UI 변경은 없다.
- 실제 웹에서 같은 기존 통화의 결과를 재질문했다. Sol이 get_phone_call을 호출하고
  이후 인사 전사·회선 종료·음성 전송 추정과 실제 청취 미확인을 구분해 답했다.
  이전 요약은 종료 요청 시점 기록이라고 설명했다. 응답 completed를 확인했다.
- Langfuse에서 main-chat·모델 2회·get_phone_call의 4개 observation을 확인했으며
  input/output은 모두 비어 있었다. 해당 대화의 통화는 기존 1건 그대로, 활성 통화 0건이다.
- 실제 전화·Google 작업은 실행하지 않았다. 모델 답변의 지속적 정확성이나 자동 전사의
  실제 음성 일치를 보장하는 검증은 아니며, 기록 조회 근거가 메인 모델에 전달됨을 확인했다.
