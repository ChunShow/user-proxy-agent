# 종료 사유와 회선 종료 근거 구분

상태: completed (코드·모사·실제 텍스트 모델·기존 웹 기록 검증). 승인: 청취 검증 후 정상적인 종료 요청을 거절로 표시하는 문제와
종료 기록/결과 표시 개선을 제안했고 사용자가 “진행해줘.”라고 승인했다.

## 원인과 범위

Live 위임 도구에는 일반적인 상대 종료 요청 코드가 없고, completion_review도 목표 달성/
거절만 종료 대상으로 안내한다. UI는 audio_drained만으로 시스템이 회선을 끊었다고 표현한다.
회선이 이미 종료됐으면 hangup 호출을 생략하지만 그 분기의 명시적 추적은 없다.

1. recipient_requested_end를 추가하고 업무 달성/거절/일반 종료 요청을 구분한다.
   위임 지침·Live 허용 코드·결과 조회·로그에서 같은 의미를 유지한다.
2. 종료 확인 시 end_report에 carrier_action을 저장한다. 시스템 종료 API 요청 이력과
   정리 시 이미 종료된 상태를 구분하며, 둘 다 실제 종료 주체의 완전한 증거는 아니다.
   이미 종료된 회선을 관측한 경로를 감사 이벤트로 남긴다. 기존 기록은 소급 추정하지 않는다.
3. 카드와 모델 지침은 음성 전송/무음 확인·회선 종료·청취 여부를 분리한다.
   과거 recipient_declined는 일반 종료 요청도 포함됐으므로 거절로만 단정하지 않는다.
4. 회귀 테스트 실패를 확인한 뒤 최소 수정, 관련 검사와 실제 모델의 합성 대화 분류를
   검증한다. 실제 전화/Google 작업은 하지 않는다. 기존 기록과 과거 생성 보고 본문은 보존한다.

대상: calls/delegation.py, live_bridge.py, manager.py, tools.py, reports.py,
chat/runtime.py, observability.py, web/src/chat/callResult.ts와 관련 검사.
DB 스키마/화면 레이아웃/음성 설정은 바꾸지 않는다.
완료 기준: 일반 종료 요청 수용, 거절과 분리, 회선 종료 근거 없는 자동 종료 단정 방지,
정리 전 종료/종료 요청/실패 경로 회귀 통과 및 로컬 적용·기록·커밋.

## 결과

- 일반 종료 요청 코드를 위임/Live/조회/추적에 연결했다. 업무 완료와 명시적 거절의 기준을
  도구 설명과 보조 종료 판단 지침에 명시했다. 기존 recipient_declined 기록은 변경하지 않는다.
- 회선 종료 API 요청 시 carrier_action=hangup_requested를 저장하고, 종료 확인 때 요청
  이력이 없으면 already_ended로 저장한다. carrier_already_ended는 SQLite/Langfuse 허용
  이벤트다. 실패 뒤 재확인에서도 기존 요청 이력을 보존한다. 실제 종료 주체는 단정하지 않는다.
- UI는 과거 코드의 거절/일반 종료 모호성과 회선 종료 주체 미확인을 명시한다. 음성 전송/
  무음 확인을 시스템 자동 종료로 표현하지 않는다. 새 일반 종료 요청은 별도로 표시한다.
  메인 채팅과 자동 결과 보고에도 같은 근거 해석을 적용했다.
- 실패 재현: 신규 종료 사유가 Live까지 도달하지 못함, carrier_action 없음, 기존 UI의
  과도한 종료 표현을 확인했다. 테스트 준비 중 비동기 대기 누락과 일괄 편집 범위 오류를
  수정한 뒤 다시 검증했다. 최종 통화 회귀 218개, 웹 36개, Ruff/ESLint/TypeScript/빌드 통과.
- 실제 설정의 메인 모델과 합성 전사/임시 DB/모사 음성 명령으로 3개 분류를 검증했다.
  일반 “오늘은 여기까지” → recipient_requested_end, “관심 없으니 다시 연락하지 마세요”
  → recipient_declined, 요청된 테스트 가능 여부 확인 완료 → goal_achieved. 모두 일치했다.
- 실제 결과 보고 모델에도 합성 일반 종료/이미 종료된 회선 기록을 넣었다. 미확인 업무와
  회선 종료 상태를 구분했고 누가 먼저 종료했는지는 확인되지 않았다고 설명했다.
- 활성 회선/진행 중 응답이 없음을 확인하고 로컬 dev 서버를 재시작했다. health 정상과
  기존 청취 테스트 카드의 변경된 안내를 브라우저에서 확인했다. 과거 생성 요약은 보존됐다.

실제 발신·Google 작업은 없었다. 이번 결과는 실제 음성/회선의 새 종료 분기 검증은 아니며,
짧은 합성 모델 사례가 모든 자연어 변형의 분류를 보장하지 않는다. 상세 통신사 종료 원인이나
상대 휴대폰의 종료 행위는 여전히 직접 관측하지 못한다.
