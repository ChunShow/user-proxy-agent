# Google 일정과 실제 통화 연계 검증

상태: 검증 실행 완료 — 안내·인사 실제 청취 확인, 사용자 직접 종료

## 승인과 범위

직전 Google 쓰기 검증 보고에서 제안한 다음 작업은 Google 일정 확인과 실제 전화를
이어 검증하는 것이었다. 사용자가 “좋아 진행해줘”로 승인했다.
기존 승인된 본인 시험 번호(끝자리 9615)에 웹 채팅으로 한 번 발신한다.
실제 예약·일정 수정·메일 발송은 포함하지 않는다. 구현 변경 없이 기존 기능을 검증한다.

## 시나리오와 검증

- 2026-09-28 Asia/Seoul 09:00–09:10 및 10:00–10:10의 가능 여부를 통화 중 확인한다.
- AI 테스트 통화임을 밝히고, Live → DeepAgents → Google Calendar 조회를 거쳐 안내한다.
- 비어 있는 시간의 상대방 가능 여부를 질문하고 답을 확인한 뒤 종료한다.
- 일정 제목·설명은 전달하지 않으며 빈 시간을 실제 예약 동의로 해석하지 않는다.
- 실제 Google 결과, 웹 통화 내역, 위임 상태, 종료 결과를 구분해 기록한다.
- 생성된 음성과 상대방의 실제 청취 여부는 구분한다. 필요하면 사용자 피드백으로 확인한다.

## 사전 점검

- 기존 활성 통화 0건.
- `uv run python ../scripts/check_live_calls.py --preflight`: carrier/발신번호/Live/control socket 정상.
  이 점검은 발신이나 Live 음성 생성 검증을 하지 않는다.
- Google 읽기: 오전 9시 구간 busy 1건, 오전 10시 구간 busy 0건. 두 조회 모두 잘림 없음.

## 결과

- 웹 채팅으로 본인 번호에 1회 발신했고 실제 연결·종료를 확인했다. 추가 발신 없음.
- 일반 통화 업무 위임 1회가 applied로 끝났다(약 6.2초). 사전 정답을 통화 목적에 넣지 않았다.
- 웹 전사에 오전 9시 충돌, 오전 10시 비어 있음 안내와 10시 가능 여부 질문이 나타났다.
  사전 Google 실제 조회 결과와 일치한다. 상대방 긍정 답변 및 마지막 인사도 표시됐다.
- 현재 로그는 개별 Calendar 도구 호출/응답을 저장하지 않는다. 따라서 위임 적용과 안내의
  일치까지 확인했으며, 이 회선의 Google 호출 자체를 독립 감사 기록으로 증명하지는 못한다.
- 브라우저 듣기를 켜서 ‘통화 소리를 듣고 있어요 · 마이크 꺼짐’ 상태를 확인했다.
  이 UI 상태만으로 실제 출력 음질·사용자 청취를 검증했다고 주장하지 않는다.
- 종료 보조 판단에서 `end_tool_requested(reason=goal_achieved)`가 기록됐다.
  그 뒤 `end_requested`/`end_playback_finished`가 기록되기 전 회선이 끝났다.
  `stop_requested=0`, `end_report={}`, `outcome=incomplete`, 오류 코드 없음.
  웹 직접 종료 요청은 없었으나 휴대폰에서 종료했는지는 서버 기록으로 구별할 수 없다.
  자동 종료 성공을 입증하지 않는다. 사용자가 “안내와 인사를 듣고 제가 직접 끊었어요”로
  실제 안내·인사 청취와 휴대폰 직접 종료를 확인했다.
- 새로고침 후 종료 카드 복원, 활성 통화 0건, 질문 대기 0건, 새 쓰기 실행안 0건.
  메인 채팅도 completed이며 오류 코드 없음.
- 이번 작업은 기존 기능의 실서비스 검증과 문서 기록이다. 코드 변경·추가 자동 테스트 없음.

## 남은 확인

- 사용자 실제 청취 및 직접 종료는 확인 완료. 브라우저 스피커 출력 음질은 별도 미검증.
- 개별 Calendar 도구 호출의 최소 감사 정보, 종료 도구 호출 뒤 적용 전 회선 종료 원인의
  세부 검증은 후속 과제다. 이번 기록을 자동 종료 개선 완료로 취급하지 않는다.
- 개인 번호, 전사 원문, 인증정보는 저장소에 기록하지 않았다.
