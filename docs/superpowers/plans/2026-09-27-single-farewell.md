# 종료 인사와 결과 설명 중복 줄이기

상태: completed (모사·실제 Sol 합성 전사 검증, 새 실회선 미검증)

## 승인·원인

직전 실통화에서 자동 종료는 확인했으나 인사 뒤 결과 요약이 다시 발화됐다.
중복 발화 개선을 제안했고 사용자가 “좋아 진행해줘.”라고 승인했다.
Live 선행 인사 뒤 bridge가 최종 backend 답변 전체와 추가 인사를 강제하는 경로를 확인했다.

## 범위·작업

- Live는 최종 인사 전에 종료 판단을 위임하도록 지시한다.
- Sol의 내부 summary와 상대에게 읽을 최종 답변을 구분한다. 최종 답변은 상대에게 직접
  말하는 내용이며 이미 전달한 결과를 반복하거나 통화를 마쳤다는 사후 보고를 읽지 않는다.
- end_call에 farewell_already_said 옵션을 추가한다. 필요한 정보·인사가 이미 전달됐고
  추가 전달이 없을 때만 사용한다. 이때 backend 최종 답변을 다시 읽지 않고 기존 유효 음성의
  ACK·무음·버퍼 배출을 확인한다. 기본 경로는 필요한 결과와 인사를 한 번의 발화로 요청한다.
- 새 상대 발화·조건 변경 보호와 25초 상한은 유지한다. 침묵만으로 성공을 확정하지 않는다.
- 정책 전달, 이미 인사한 경로의 추가 음성 없음/ACK 대기/새 상대 발화 보호를 회귀 검사한다.
  실제 Sol 모델에 합성 전사를 넣어 모드 선택·미전달 결과 보존을 검증한다. 추가 실제 발신 없음.

## 파일·완료 기준

calls/live.py, delegation.py, live_bridge.py 및 해당 테스트/검증 기록.
반복을 요구하던 제어 경로를 제거하고 기존 종료 검사를 유지한다.
모델 판단/음성 생성은 확률적이므로 모사 통과를 실통화의 중복 제거 보장으로 표현하지 않는다.

## 결과와 검증

- Live가 종료 판단 전 인사를 먼저 하지 않도록 지시하고, backend 최종 답변과
  내부 summary를 명확히 구분했다. 무조건 결과 재낭독+별도 인사를 요구하던 문구를 제거했다.
- end_call의 farewell_already_said=true는 bridge에 전달되어 최종 답변을 음성 지시에
  포함하지 않는다. 기존 유효 음성/큐의 재생 ACK와 무음 조건을 확인한다.
  이 선택 여부를 end_requested 메타데이터에도 남긴다. 음성이 없으면 성공으로 판정하지 않는다.
- 기존 backend 전체와 신규 3개 회귀를 합친 268개 테스트 통과. Ruff 검사 통과.
- 실제 Sol 모델 + 실제 DelegationCoordinator/end_call 도구에 합성 전사 2개를 넣었다.
  인사 완료 사례는 goal_achieved·farewell_already_said=true, 최종 답변은 내부 종료 표시만 반환.
  미전달 사용자 답변 사례는 기본 발화 경로를 선택해 오후 6시 가능 안내와 짧은 인사를 유지했다.
  이 검증은 실제 회선/Live 음성 생성이 아니며 새 전화·Google 조회·메일 발송은 없었다.
- 코드 차이와 안전 조건을 검토했다. 상대 새 발화 취소와 기존 재생 대기 상한은 유지했다.

## 남은 확인

새 실제 Live 음성과 본인 통화에서 한 번의 인사와 종료를 확인해야 한다.
모델이 인사 완료 여부를 잘못 판단할 가능성과 음성 활동/ACK 판정의 추정 성격은 남아 있다.
