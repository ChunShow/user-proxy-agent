# 종료 인사와 결과 설명 중복 줄이기

상태: completed (모사·실제 Sol 합성 전사 및 실회선 종료 기록 확인, 사용자 청취 확인)

## 승인·원인

직전 실통화에서 자동 종료는 확인했으나 인사 뒤 결과 요약이 다시 발화됐다.
중복 발화 개선을 제안했고 사용자가 “좋아 진행해줘.”라고 승인했다.
Live 선행 인사 뒤 bridge가 최종 backend 답변 전체와 추가 인사를 강제하는 경로를 확인했다.

## 범위·작업

- Live는 최종 인사 전에 종료 판단을 위임하도록 지시한다.
- Sol의 내부 summary와 상대에게 읽을 최종 답변을 구분한다. 최종 답변은 상대에게 직접
  말하는 내용이며 이미 전달한 결과를 반복하거나 통화를 마쳤다는 사후 보고를 읽지 않는다.
- end_call에 farewell_already_said 옵션을 추가한다. 필요한 정보·인사가 이미 전달됐고
  추가 전달이 없을 때만 사용한다. 이때 backend 최종 답변을 다시 읽지 않고 기존 유효 음성의
  ACK·무음·버퍼 배출을 확인한다. 기본 경로는 필요한 결과와 인사를 한 번의 발화로 요청한다.
- 새 상대 발화·조건 변경 보호와 25초 상한은 유지한다. 침묵만으로 성공을 확정하지 않는다.
- 정책 전달, 이미 인사한 경로의 추가 음성 없음/ACK 대기/새 상대 발화 보호를 회귀 검사한다.
  실제 Sol 모델에 합성 전사를 넣어 모드 선택·미전달 결과 보존을 검증한다. 추가 실제 발신 없음.

## 파일·완료 기준

calls/live.py, delegation.py, live_bridge.py 및 해당 테스트/검증 기록.
반복을 요구하던 제어 경로를 제거하고 기존 종료 검사를 유지한다.
모델 판단/음성 생성은 확률적이므로 모사 통과를 실통화의 중복 제거 보장으로 표현하지 않는다.

## 결과와 검증

- Live가 종료 판단 전 인사를 먼저 하지 않도록 지시하고, backend 최종 답변과
  내부 summary를 명확히 구분했다. 무조건 결과 재낭독+별도 인사를 요구하던 문구를 제거했다.
- end_call의 farewell_already_said=true는 bridge에 전달되어 최종 답변을 음성 지시에
  포함하지 않는다. 기존 유효 음성/큐의 재생 ACK와 무음 조건을 확인한다.
  이 선택 여부를 end_requested 메타데이터에도 남긴다. 음성이 없으면 성공으로 판정하지 않는다.
- 기존 backend 전체와 신규 3개 회귀를 합친 268개 테스트 통과. Ruff 검사 통과.
- 실제 Sol 모델 + 실제 DelegationCoordinator/end_call 도구에 합성 전사 2개를 넣었다.
  인사 완료 사례는 goal_achieved·farewell_already_said=true, 최종 답변은 내부 종료 표시만 반환.
  미전달 사용자 답변 사례는 기본 발화 경로를 선택해 오후 6시 가능 안내와 짧은 인사를 유지했다.
  이 검증은 실제 회선/Live 음성 생성이 아니며 새 전화·Google 조회·메일 발송은 없었다.
- 코드 차이와 안전 조건을 검토했다. 상대 새 발화 취소와 기존 재생 대기 상한은 유지했다.

## 남은 확인

후속 실회선 전사와 서버 기록에서 한 번의 인사와 종료를 확인했다. 사용자도 인사 한 번 후 자동 종료됐다고 확인했다.
모델이 인사 완료 여부를 잘못 판단할 가능성과 음성 활동/ACK 판정의 추정 성격은 남아 있다.

## 실제 통화 후속 검증 승인

구현 결과 보고 뒤 사용자가 “확인해줘.”라고 요청했다. 기존 본인 번호(끝자리 9615)에
웹 채팅으로 1회 발신하여 짧은 통화 가능 여부 확인, 한 번의 인사와 자동 종료를 검증한다.
웹 전사·종료 이벤트·Langfuse 추적과 사용자 청취 확인을 비교한다. 일정·메일 변경은 없으며
실패 시 자동 재발신하지 않는다. 이번 후속 작업은 검증과 기록 범위다.

검증 상태: 서버·웹·Langfuse 및 사용자 실제 청취 확인 완료.

### 실회선 결과

- 웹 개발 서버가 중단되어 있어 재시작했다. 발신 전 ClawOps 계정·유휴 발신번호·제어 소켓
  준비 확인 성공, 활성 통화 0건을 확인했다. 기존 backend는 개선 커밋 적용 상태였다.
- 새 웹 대화에서 본인 번호에 정확히 1회 발신했다. 상대 답변 후 종료 위임이 실행됐고,
  전사에는 짧은 대기 발화 뒤 최종 인사 1회만 남았다. 인사 뒤 결과 요약·추가 인사는 없었다.
- end_call → end_requested(farewell_already_said=false) → 인사 명령 ACK(394ms) →
  end_playback_finished(audio_drained, 7174ms) → carrier_end_confirmed(completed)를 확인했다.
  7.174초는 종료 요청부터 재생 판정까지이며, 인사 발화 시간도 포함한다.
- 마지막 유효 음성 163680bytes, ACK 178400bytes, 대기 음성 패킷 0, 부분 버퍼 0,
  출력 무음 2027ms였다. 직접 종료 요청 0, 오류 없음, 최종 활성 통화 0건이다.
  미디어 루프 종료 뒤 회선 completed를 확인했으며 별도 hangup API 요청 기록은 없다.
- 같은 Langfuse trace의 16개 observation에서 main-chat·start_phone_call·call-delegation·
  end_call과 종료 단계 8개를 확인했다. 원문 input/output은 저장되지 않았다.
- 웹 새로고침 뒤 종료 상태와 결과가 복원됐다. Google 조회·등록·발송은 없었다.
- 사용자는 “네, 인사 한 번 후 자동으로 끊겼어요”라고 확인했다.
  이미 인사한 경로(farewell_already_said=true)는 이번 실회선에서 선택되지 않았다.

### 발견한 표시 제한

화면 결과 요약은 종료 결정 당시 Sol의 내부 요약이므로 인사 전 상태가 남을 수 있다.
이번에도 이후 인사 전사가 존재하지만 요약에는 아직 인사하지 않았다는 결정 당시 문장이 남았다.
또한 Live 재생 판정은 추정이므로 화면은 마지막 음성 확정 여부를 보수적으로 표시한다.
이번 작업은 검증·기록만 수행했으며 이 표시 동작의 변경은 포함하지 않았다.
원시 전사·전화번호·통화 식별자는 Git에 추가하지 않았다.
