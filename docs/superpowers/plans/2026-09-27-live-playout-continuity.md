# Live 음성 공급 공백 후속 개선

상태: completed (전화 없는 중계 개선·검증 범위).
승인: 앞선 한국어 음성 비교·필요한 중계 보완 요청과, marin 선호 확인 후 남은 간헐
끊김을 설명한 데 대한 사용자의 “개선해줘.”를 적용한다. 전화 없는 검증 범위를 이어간다.

1. 기존 9개 실제 API 기록을 가상 시계로 기존 play 코드에 재입력해 공급 공백을 재현한다.
2. 시작/충분한 무음에서만 짧은 출력 여유분을 보충하는 후보를 비교한다.
   음성 패킷 삭제·RMS 기반 강제 취소·사용자 말투/음성 변경은 하지 않는다.
3. 회귀 테스트를 먼저 실패시킨 뒤 검증된 후보를 적용한다. 여유분 보충은 유한 시간이며
   취소/clear/자동 종료 판단을 막지 않아야 한다. 추가 지연도 함께 계측한다.
4. 저장된 9개 기록의 공백/전체 바이트 보존, 정상/지연 패턴, 종료/직접 중단을 검증한다.
   실제 API 합성 입력 1회로 경로를 확인하고, 실제 전화는 걸지 않는다.
5. 비교 음성·문서·커밋을 남기고 활성 작업이 없을 때 서버에 반영한다.

파일: calls/live_bridge.py, tests/calls/test_live_playout.py, scripts/replay_live_audio.py,
관련 문서. 샘플/원본 이벤트는 ignored var에만 둔다.
완료 기준: 재현된 발성 중 40ms 초과 공급 공백의 감소, 바이트 보존, 정상 스트림에 과도한
지연 없음, 종료 회귀 통과. 네트워크 무제한 지연·모델 자체 발음 끊김·실회선은 별도 한계다.

## 적용과 검증

- 시작 또는 200ms 이상 저음량 구간에서 공급량이 적을 때 최대 120ms씩 기다려
  20ms 패킷 6개를 확보한다. 패킷을 삭제하지 않으며 충분히 쌓인 스트림에는 대기를 추가하지 않는다.
  의도적인 대기 후 전송 시계를 재설정해 급한 따라잡기 전송으로 여유분이 소진되지 않게 했다.
- 잠금 없이 유한 횟수로 기다린다. clear/취소 시 이전 패킷을 내보내지 않고, 새 생성량이
  없으면 끝의 무음에 반복 대기하지 않는다. 개선된 한국어 지시와 marin은 유지했다.
- 회귀 테스트를 기존 코드에서 실패시킨 뒤 적용했다. 시작/공급 지연, 짧은 마지막 패킷,
  clear/취소, 이미 쌓인 스트림의 원래 속도를 검증한다.
- 기존 실제 API 기록 9개와 새 기록 1개를 동일한 가상 수신 시계로 재생했다.
  기존 방식에서 재현된 발성 패킷 사이 공급 공백 99ms·43ms·103ms가 수정 후 모두
  40ms 이하가 됐다. 10개 기록 모두 전체 음성 바이트가 보존됐다.
- 대가로 발성 패킷 전달 지연은 실행별 중앙값 62~170ms 증가했고 전체 최대 증가는
  229ms였다. 120ms는 보충 1회 한도이며 전체 추가 지연 한도가 아니다.
- 새 실제 Live API 32초 실행 1회: 오류 없음, 허용 음성 marin, 40ms 초과 발성 공급 공백 없음.
  테스트 시간 내 전송된 오디오는 생성 원본의 정확한 접두부였다. 종료 시한 뒤의 무음까지
  모두 전송됐다고 주장하지 않는다. 모사 출력 대기량 최대 420ms를 관측했다.
- `AGENT_SERVICE_ENV_FILE=/dev/null uv run pytest tests/calls -q`: 206 passed.
  backend에서 `uv run ruff check --config pyproject.toml . ../scripts`: 통과.
- 활성 통화와 실행 중 채팅이 없는 상태에서 로컬 backend를 재시작했다.
  비교 페이지 `http://127.0.0.1:9122/continuity.html`에 같은 음성의 전후 재생을 제공한다.

원본·계측·비교 WAV는 ignored `var/korean-live-replay/1790500851-2837062/`와
`var/korean-live-lab/`에만 보관한다. 재현 도구는 `scripts/replay_live_audio.py`다.
입력은 합성 음성이며 회선과 ACK는 모사다. 실제 발신·Google 작업은 없었다.
실회선 청취 개선, 모델 자체 발음·억양, 의미 있는 끼어들기 성공률을 입증한 결과는 아니다.
