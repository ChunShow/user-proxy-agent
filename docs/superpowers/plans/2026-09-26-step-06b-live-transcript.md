# 6B: 실시간 통화 내역 화면 구현 계획

> **실행 방식:** 컨펌 후 한 작업씩 직접 구현한다. 각 작업의 행동 검사를 먼저 작성하고,
> 실패 재현 → 구현 → 검증 → 로컬 커밋 순서로 진행한다. 병렬 위임은 하지 않는다.

**상태:** in_progress

**목표:** 사용자가 같은 채팅 화면에서 실제 통화 내용을 읽고, 확인 질문에 답하거나 통화를 종료한다.

**구조:** 기존 `call_activity`와 owner 범위의 activity API를 재사용한다. 웹은 펼친 통화의
이벤트를 커서로 증분 조회하고, 전사 조각을 화자별 표시 구간으로 합친다. 음성 송신/재생 ACK는
통화 전체의 진행 정보로 제공하고 개별 문장의 청취 완료로 간주하지 않는다.

**기술:** 기존 FastAPI·SQLite·React·TypeScript·Vite. 새 서비스나 패키지는 추가하지 않는다.

**설계 근거:** `docs/product.md`, `docs/roadmap.md`의 6B 및 아래 화면/데이터 설계.

## 승인 기록

사용자 “다음 작업 진행해줘.”에 따라 6B의 구체적인 계획을 작성했다.
계획 링크와 구현·본인 번호 테스트 통화 1회 범위를 제시한 직후 사용자가 “진행해줘.”라고 승인했다.
이 승인을 근거로 구현과 해당 테스트를 진행한다. 테스트 답변 대리 입력은 앞서 받은 승인을 유지한다.
6A의 실제 답변·인사 청취는 확인됐으나 직접 종료로 인해 자동 종료 재검증은 남아 있다.
이 미확인 항목을 6B 구현 승인이나 완료 근거와 혼동하지 않는다.

## 범위와 공통 제약

- 실제 통화 카드에 상대방/도우미 전사, 조회 상태, 음성 전송 진행을 추가한다.
- 기존 질문 답변·직접 종료·메인 채팅·대화 복원은 유지한다.
- 브라우저 음성 듣기는 7단계, 일반 채팅 추가 지시는 8단계, 앱 연결은 이후 단계다.
- 화면의 도착 속도는 활성 탭에서 약 1초 간격의 증분 조회를 목표로 한다.
  모델 자체의 전사 생성 지연은 별개이며 즉각적인 음성 자막을 보장하지 않는다.
- 기존 번호 허용 목록, 180초 상한, 한 회선 제한, 자동 재발신 금지, 소유권 검사를 유지한다.
- 원시 음성을 새로 녹음하지 않는다. 실통화 원문·키·번호는 Git/일반 로그/공개 캡처에 넣지 않는다.
- 전사는 외부 입력이다. 일반 텍스트로만 렌더링하고 HTML 실행·도구 지시·자동 링크 요청에 사용하지 않는다.
- 기존 Realtime 통화처럼 전사가 없는 기록에는 전사가 없음을 표시하고 모델 요약으로 대체하지 않는다.

## 화면 설계

기존 카드 안에 접을 수 있는 통화 내역을 둔다. 별도 오른쪽 패널은 모바일에서 다른 흐름이
필요하고, 독립 페이지는 채팅 확인 질문과의 왕복을 늘리므로 이번 범위에는 카드 방식을 선택한다.

```text
통화 제목                              통화 중
번호 · 목적

통화 내용                              접기
자동 전사 · 실제 발화와 다를 수 있습니다
상대방  내일 오후 3시는 어떠세요?
도우미  확인하고 말씀드리겠습니다.
                         [새 내용 보기]
음성 전송 중 / 음성 재생 확인 수신

확인할 질문 · 답변 버튼
                                      통화 종료
```

- 진행 중인 통화는 처음 표시될 때 펼치고, 과거 종료된 통화는 접힌 상태로 시작한다.
  사용자가 접기/펼치기를 바꾸면 자동 갱신이나 종료가 그 선택을 덮어쓰지 않는다.
- 화자 이름은 `상대방`, `도우미`다. 웹 사용자의 질문 답변은 기존 확인 카드에 둔다.
- 전사는 최대 높이가 있는 내부 영역에 표시한다. 하단을 보는 동안만 새 내용을 따라간다.
  위로 스크롤하면 위치를 유지하고 `새 내용 보기`로 다시 하단을 볼 수 있다.
- 내역이 길어져도 질문 답변과 종료 버튼이 전사 내부 스크롤에 묻히지 않도록 배치한다.
- 조회 오류 때 기존 내용은 유지하고 `내용을 갱신하지 못했어요`와 재조회 동작을 표시한다.
  전사가 아직 없는 통화, 전사가 없는 과거 기록, 로딩 상태를 구분한다.
- 전사 조각마다 스크린리더가 전체 문장을 반복 낭독하지 않도록 하고,
  버튼 키보드 조작·포커스·모바일 390px 가로 넘침을 확인한다.

### 시각 방향

사용자가 선택한 간결한 메신저 디자인을 확장한다. 기존 frontend-design 스킬을 적용한다.
새 서체나 장식은 도입하지 않고 기존 한글 시스템 서체의 본문/보조 정보 위계를 사용한다.
기존 토큰 `--canvas #f7f7f6`, `--surface #ffffff`, `--ink #262626`,
`--muted #6a6a67`, `--line #e5e5e3`, `--positive #25724e`를 재사용한다.
화자 라벨과 간결한 문단 간격으로 구분하며, 음성 상태에 과도한 성공 색상이나 움직임을 쓰지 않는다.

## 데이터와 인터페이스

### 전사 조회

기존 `GET /api/calls/{call_id}/activity?after=<event_id>`를 확장한다.
기존 `events`, `questions`를 유지하며 다음 값을 추가한다.

- `next_after: int`: 반환한 마지막 이벤트 ID, 빈 페이지는 요청 커서를 유지한다.
- `has_more: bool`: 같은 통화에서 다음 페이지가 남았는지 101건 조회로 판정한다. 한 페이지 최대 100건.
- `terminal: bool`: ended/failed/canceled 여부. 최종 페이지까지 읽은 후 반복 조회를 멈추는 기준이다.
- `after`는 0 이상의 정수다. 권한 없는 통화는 기존과 같이 404, 응답은 no-store다.

기존 이벤트 형태 `{id, call_id, kind, content, created_at}`를 유지한다.
전사는 `kind=transcript`, `content={role: caller|assistant, text, start_ms, end_ms}`다.
다른 종류의 이벤트도 커서는 진행시키되 전사 본문으로 표시하지 않는다.

### 전사 조각 합치기

- 서버 이벤트 ID로 중복 제거하고 정렬한다. 기존 text 조각의 공백을 임의 삽입/삭제하지 않는다.
- 수신 순서상 같은 화자의 연속 조각을 표시 구간으로 합친다. 첫 이벤트 ID가 구간 ID다.
- 화자 전환 또는 이전 조각 수신 후 2초 이상 간격이면 새 구간을 시작한다.
  이 경계는 읽기 편의를 위한 것이며 실제 발화 완료/확정 이벤트로 표현하지 않는다.
- 현재 어댑터가 제공하는 전사만 사용한다. 확정 이벤트가 없는 문장에 `확정` 배지를 붙이지 않는다.
  모델의 시간 필드가 없는 예전 데이터도 수신 시각과 이벤트 ID로 표시 가능해야 한다.
- 출력 전사는 모델이 생성한 발화 내용이다. 상대방이 그 문장 전체를 들었다는 표시를 하지 않는다.

### 음성 전송 상태

새 `kind=audio_progress` 이벤트를 같은 저장소에 기록한다.
`content={generated_bytes, sent_bytes, playback_acked_bytes, interrupted}`로 구성한다.
이는 해당 통화 스트림의 누적 값이며 전사 시간과 일대일 대응하지 않는다.

- `LiveBridge`의 현재 카운터와 출력 음성 수신 카운터로 만든다.
- 오디오 프레임/ACK마다 DB를 쓰지 않는다. 독립 태스크가 최대 1초에 1회, 값이 바뀔 때만 기록한다.
- 종료 직전 마지막 값을 남긴 뒤 작업을 정리한다. 진행 정보 저장 때문에 음성 송신 루프를 막지 않는다.
- 직접 종료의 출력 지우기는 `interrupted=true`로 남긴다. 최종 ACK보다 뒤의 생성 내용을
  재생 완료로 간주하지 않는다. 이 값은 발신/자동 종료의 판단을 바꾸지 않는다.
- 화면은 전송 중/재생 확인 수신/전송 종료 상태를 통화 전체 수준으로 표시한다.
  마지막 진행 이벤트가 없거나 오래되면 `음성 상태 확인 중`으로 표현한다.

## 작업 4: 실제 확인과 완료 기록

- [ ] 먼저 저장된 본인 테스트 통화로 새로고침 후 내역 복원을 확인한다. 원문은 Git에 넣지 않는다.
- [ ] 구현 컨펌에 본인 번호의 테스트 발신 1회를 포함하는지 함께 확인한다. 승인받으면
  웹에서 시간 제안 → 확인 질문 → 승인된 가상 답변 입력 → 음성 전달 → 자동 종료를 확인한다.
  마지막 인사 뒤 직접 종료하지 않고 기다려 6A에서 남은 자동 종료 검증도 함께 수행한다.
- [ ] 실제 회선/모델의 음질 문제나 실패가 생기면 상태를 조사하고 자동 재발신하지 않는다.
  새 구조나 자동 종료 로직의 변경이 필요하면 그 변경 계획을 별도로 제시한다.
- [ ] 정확한 검증 범위와 남은 제한을 이 문서·제품 문서·로드맵·통화 운영 문서에 반영한다.
  실제 전사 표시 성공, 모델 음성 생성, ACK, 사용자 청취 확인, 회선 종료를 각각 기록한다.

## 완료 기준

전사가 통화 중 화자별로 갱신되고, 100건이 넘어도 중복/누락 없이 복원되며,
질문 답변·종료·메인 채팅을 계속 사용할 수 있어야 한다. 문장 생성과 실제 청취를 혼동하는
표시가 없어야 하고, 오류/느린 응답/전환/모바일 검사가 통과해야 한다.
실제 통화 시험이 미완료라면 구현 완료와 실회선 검증 상태를 별도로 표시한다.
