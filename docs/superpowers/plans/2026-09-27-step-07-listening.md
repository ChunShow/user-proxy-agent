# 7단계: 브라우저에서 통화 듣기

상태: completed (모사 검증). 승인: 2026-09-27 자율 작업에서 사용자가 ‘둘 다 포함해 주세요’로 듣기·자동 종료 개선을 승인.
실제 발신은 하지 않는다. 기존 조용한 통화 카드 안에 듣기/듣기 중지 버튼과 연결 상태를 둔다.

- ClawOps G.711 μ-law 8kHz 수신/실제 송신 미디어를 메모리 hub에서 구독 브라우저에 전달.
- 세션 쿠키·로컬 Origin·통화 owner를 검증하는 읽기 전용 WebSocket. 오디오를 디스크에 저장하지 않는다.
- 구독 최대 2개, 대기열 제한, 느린 구독자 해제. 브라우저 연결 문제는 통화 루프에 전파하지 않는다.
- Web Audio를 명시적 사용자 클릭으로 시작. 마이크 사용 없음. 듣기 중지·통화 종료·대화 전환 때 자원 해제.
- 합성 μ-law를 decode/재생하고 E2E에서 연결/해제/실패/모바일을 확인. 실제 청취 품질은 추후 실제 통화로 확인.
- 자동 종료는 별도 계획에서 원인 경로, 종료 요청/취소 기록, 재판단을 다룬다.

검증: 단위 hub backpressure·미디어 분기, WS owner/Origin/종료, 브라우저 WebAudio 모사, 기존 통화 회귀 검사.

## 결과

전체 검사 backend 228·web 25, Ruff/TypeScript/ESLint/build 통과.
관련 Chrome E2E 4 통과. 실제 Web Audio에 양방향 합성 μ-law를 넣어 재생 시작을 확인하고,
듣기 중지·대화 전환의 소켓 정리 및 통화 종료 버튼 유지 확인. 실제 발신·청취 시험 없음.
모니터는 통화 기록 재생이 아니며 접속 이후 음성만 전달한다. 청취 음성은 별도로 저장하지 않는다.
