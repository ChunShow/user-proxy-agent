# 공유 주소의 모바일 로그인

상태: implemented (실제 모바일 앱 내 브라우저 확인 대기)

사용자가 앱 내 브라우저에서도 공유 페이지를 열도록 요청했다. 현재 HTTP Basic 인증은
익명 요청에 빈 401과 인증 팝업 요구를 반환한다. 이를 일반 HTML 비밀번호 폼으로 교체한다.
공유 주소·기존 비밀번호와 로컬 앱의 데이터/세션 분리 정책은 유지한다.

- 기존 Caddy 앞단 인증만 별도의 loopback FastAPI 로그인 서비스로 대체한다.
- 폼 POST → Secure/HttpOnly/SameSite 쿠키 → 홈 화면. 앱 로그인/기기 간 동기화는 추가하지 않는다.
- 비밀번호·서명 키는 Git 제외 설정에 저장하며 URL·로그·프런트엔드에 넣지 않는다.
- Origin 확인, 로그인 시도 제한, 12시간 쿠키 만료, API/웹소켓 인증을 검증한다.
- 기존 CSS의 흰색·중립색·시스템 한글 글꼴을 사용하고 320px 화면·키보드 입력을 확인한다.
- HTTP 검사와 모바일 크기 브라우저 검사 후 현재 공유 게이트웨이에 적용한다.
  실제 앱 내 브라우저의 기기별 검증은 사용자의 기기에서 확인해야 한다.

## 결과

- 별도 인증 서비스와 Secure·HttpOnly 쿠키를 기존 공유 주소에 적용했다.
- 인증 자동 검사 4개 통과: 폼 이동, 비밀번호·Origin, 쿠키 위변조/만료, 시도·본문 크기 제한.
- 공개 주소 HTTP 검사: 익명 폼 200, 로그인 후 UI/API/세션 접근, 잘못된 비밀번호 거부,
  다른 Origin 거부, 로그아웃 후 접근 차단 확인.
- Chrome 320px 화면에서 폼·레이블·버튼이 잘리지 않고 표시됨을 확인했다.
- 검증용 Chrome 폼 제출은 `ERR_BLOCKED_BY_CLIENT`로 차단됐다. 서버에 해당 POST가
  도달하지 않아 브라우저 로그인 완료는 확인하지 못했다. HTTP 통과를 실제 앱 검증으로
  간주하지 않으며 기기에서 최종 확인이 필요하다.
- 전화 발신·모델 호출·Google 쓰기는 하지 않았다.
- 실행과 제한은 [공유 로그인 안내](../../remote-access.md)에 기록했다.

## 공유 비밀번호 변경

사용자가 5자 비밀번호로 변경을 명시 요청했다. 최소 길이를 5자로 조정하고, 비공개 설정에만
새 값을 저장한다. 서명 키도 교체하여 기존 접근 쿠키를 무효화한다. 기존 비밀번호 거부와
새 비밀번호 로그인, 인증 테스트를 확인한다. 실제 비밀번호는 Git에 기록하지 않는다.

변경 완료: 인증·세션 검사 8개 및 Ruff 통과. 공유 주소에서 기존 비밀번호와 기존 쿠키의
거부, 새 비밀번호 로그인 후 UI/API 접근 성공을 확인했다. 비공개 설정만 새 값으로 갱신했고
인증 프로세스만 재시작했다. 제품 서버와 Cloudflare 주소는 유지했다.
