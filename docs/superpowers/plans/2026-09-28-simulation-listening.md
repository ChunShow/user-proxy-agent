# 가상 ARS 통화 듣기 수정

상태: complete
승인: 사용자가 “가상 ARS의 경우 음성 듣기 기능이 지원이 안되는데 지원 되게 해줘”라고
요청하고, 통화 중 듣기 버튼을 눌러도 안 들린다고 확인했다. 기존 청취 기능의 연결 오류 수정.

## 원인과 범위

공유 Caddy의 forward_auth가 WebSocket Upgrade 헤더를 인증 서비스로 전달한다.
HTTP 전용 /_access/verify가 WebSocket 요청을 403으로 거부한 기록을 확인했다.
인증 하위 요청에서만 Upgrade/Connection 헤더를 제거한다. 실제 API로의 WebSocket,
로그인 쿠키 확인, 허용 Origin 및 통화 소유권 검사는 유지한다.

- [x] 실제 Caddy를 사용하는 실패 재현/회귀 검사: 인증 전 거부, 인증 후 양방향 음성 트랙 수신.
- [x] 비공개 운영 Caddyfile 수정과 재사용 가능한 설정 템플릿 저장.
- [x] 로컬 청취 경로의 자동 검사, 공유 Chrome에서 가상 통화 듣기 연결 확인.
- [x] 관련 자동 검사, 문서·기록, 실행 중 게이트웨이에 적용.

실제 전화 발신·녹음 저장 기능 추가·자동 재생 정책 변경은 범위 밖이다.

## 검증 결과

- 수정 전: 실제 Caddy 회귀 검사에서 인증된 WebSocket도 HTTP 403으로 실패했다.
- 수정 후: 공유 프록시·인증·세션·청취 관련 pytest 12개 통과. 새 검사 Ruff 통과.
- 운영 Caddy 설정 검증 후 활성 통화 0건에서 해당 공유 게이트웨이만 재시작했다.
- 실제 공유 HTTPS 페이지의 디버깅 대화에서 가상 ARS 통화를 승인하고 ‘통화 듣기’를 눌렀다.
  ARS 메뉴 전사와 함께 ‘통화 소리를 듣고 있어요 · 마이크 꺼짐’이 표시됐다.
  화면 기록: `var/listening-fix/shared-listening.png` (Git 제외).
- 가상 ARS·실제 모델 통화만 사용했다. ClawOps 실제 발신은 없었다.
  물리 스피커의 청감은 자동으로 확정하지 않는다. 로컬 Chrome 별도 청취 반복 대신
  기존 로컬 WebSocket 자동 검사와 실제 공유 브라우저 연결을 검증했다.
