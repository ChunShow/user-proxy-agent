# 채팅 응답 마크다운 표시

상태: completed. 사용자가 기능 작업을 마치고 UI 다듬기로 전환한 뒤 “현재 마크다운
형식으로 출력 반영 안되더라”라고 지적했다. 실제 화면에서 강조/목록 기호의 원문 노출을 확인했다.
기존 MessageList는 모든 응답을 plain text div로 표시한다. 이 명확한 표시 결함을 먼저 수정한다.

도우미 응답에만 react-markdown + remark-gfm을 적용한다. 사용자 입력·자동 전사·확인 카드의
실행 내용은 그대로 둔다. 제목/목록/강조/링크/인용/코드/표에 기존 흑백 스타일과 읽기 쉬운
간격을 적용한다. 모바일의 긴 코드/표는 메시지 내부에서 가로 스크롤한다.
HTML을 실행하지 않으며 외부 이미지는 자동으로 불러오지 않는다. 링크는 안전한 프로토콜만
허용하고 새 탭으로 연다. 저장 내용/모델 지침/전화·Google 로직은 변경하지 않는다.

렌더링과 사용자 원문 유지, HTML/위험 링크/외부 이미지, 미완성 스트리밍 마크다운의 테스트를
먼저 실패시킨 뒤 구현한다. 데스크톱 실제 대화와 모바일 합성 표시, 기존 웹 검사/정적 검사/
빌드를 확인한다. 실제 모델·전화·메일 호출 없이 로컬 적용·문서·커밋까지 완료한다.

대상: MessageList, 새 MarkdownMessage 컴포넌트/스타일/검사, web package/lockfile.
넓은 UI 개편은 이 표시 수정 이후 별도 작은 단위로 진행한다.


검증: 새 렌더링 검사에서 기존 구현의 4개 실패를 확인한 뒤 수정했다. 웹 42개 검사, TypeScript,
ESLint, 빌드 통과. 실제 기존 대화에 강조 표시가 적용됐고, 격리된 합성 대화에서 제목/목록/표/
인용/링크/코드를 확인했다. 모바일 표(내용 400px/표시 294px)와 긴 코드(1821px/294px)는
내부에서만 가로 스크롤했다. 페이지 전체 넘침은 없었다. 사용자 입력은 원문을 유지한다.
이후 사용자가 추가 요청한 화면 정리/대화 관리는 chat-ui-management 계획에 함께 기록했다.
