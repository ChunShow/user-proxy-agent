# 6C: 통화 종료 지연과 결과 표시 개선

**상태:** proposed
**실행 방식:** 승인 후 직접 순차 구현, 실패 재현 → 수정 → 검증 → 로컬 커밋.

## 요청과 승인 범위

6B 실제 통화에서 답변과 마지막 인사를 들은 뒤 종료됐다는 사용자 확인을 받았다.
종료 대기 및 결과 판정 개선 제안에 사용자가 “개선해줘”라고 요청했다.
이 문서는 조사에 따른 구체적인 변경 계획이다. 기존 단계별 컨펌 요청에 따라 구현 전 확인한다.
이번 계획은 로컬 구현·자동 검사까지다. 추가 실제 발신은 구현 결과를 확인한 뒤 별도로 승인받는다.

## 조사 결과

- `LiveBridge.finish`는 마지막 양방향 음성 이후 2초, 출력 큐가 완전히 비어 있음,
  `played_bytes >= sent_bytes - 640`을 모두 요구한다. 640 bytes는 현재 8kHz μ-law의 80ms다.
- 지난 실제 통화는 마지막 출력 전사 뒤에도 생성·송신량이 초당 약 8,000 bytes씩 증가했다.
  마지막 구간의 ACK는 송신량보다 약 960~1,760 bytes(120~220ms) 뒤따랐다.
  기록에는 음성 활성도·큐 길이가 없어 이후 데이터가 모두 무음이었다고 단정할 수 없다.
- 원시 음성을 사용하지 않은 로컬 재현에서, 소리가 끝났어도 무음 패킷 큐와 120ms ACK 지연을
  유지하면 현재 코드는 25초 뒤 `playback_unconfirmed`로 끝났다.
- `manager._finish`는 `played`에만 `model_reported_success`를 부여한다.
  Live의 `audio_drained`도 `incomplete`가 되고 화면은 일반 업무 미완료 문구를 보여준다.
  따라서 종료 조건과 결과 설명을 함께 다뤄야 한다.

## 선택한 방식

전체 송신량을 계속 따라잡거나 무음 큐까지 비우는 대신 **마지막 유효 음성의 끝 위치**를 추적한다.
그 위치까지 회선 재생 ACK가 도착했고, 생성 중/대기 중인 유효 음성이 없으며,
상대와 도우미의 유효 음성이 2초 이상 없을 때 기존 `audio_drained` 경로로 종료한다.
음성이 다시 생기면 대상 위치와 대기를 갱신하며, 상대가 말하면 기존 자동 종료 취소를 유지한다.

단순히 25초를 줄이거나 ACK 허용 오차를 키우면 음성 절단 위험을 가릴 수 있어 채택하지 않는다.
모델에 발화 완료 이벤트가 추가됐다는 가정도 하지 않는다. 음성 활동 기준의 추정임을 유지한다.

## 작업 1: 마지막 음성의 재생 확인을 기다리는 종료

**파일:** `backend/src/agent_service/calls/live_bridge.py`,
`backend/tests/calls/test_live_bridge.py`.

- [ ] 연속 무음과 ACK 지연으로 기존 25초 종료가 재현되는 실패 검사를 추가한다.
- [ ] 생성/송신한 유효 음성의 위치, 대기 중 유효 음성, 마지막 활동 시각을 추적한다.
  큐에서 꺼냈지만 아직 송신하지 않은 패킷과 160 bytes 미만 버퍼도 조기 종료 방지에 포함한다.
- [ ] 마지막 유효 음성 끝까지의 mark ACK를 기다린다. 100ms 주기의 mark 사이에서
  출력이 멈추는 경우에도 마지막 음성에 대한 mark를 보낼 수 있어야 한다.
  ACK 전 음성 재개, 오래된 mark, 출력 clear가 잘못된 재생 완료를 만들지 않게 한다.
- [ ] 전송된 무음이 계속 추가돼도 목표 ACK 위치는 늘리지 않는다. 생성된 새 유효 음성,
  대기 중 음성, 마지막 유효 음성의 ACK 누락은 종료를 막는다.
- [ ] 양방향 2초 조용함, 종료 요청 이후 출력 관측 조건, 상대 발화에 따른 종료 취소,
  직접 종료 우선 처리, 25초 최종 대기 상한을 유지한다.
- [ ] 마지막 보고에 원문 없는 종료 계측을 남긴다: 대기 시간, 유효 음성 목표/ACK 위치,
  마지막 활동 이후 시간, 큐/버퍼 상태, 종료 조건/상한 경로. 원시 음성을 저장하지 않는다.

**검증:** 연속 무음에서는 마지막 유효 음성·ACK·2초 조건 충족 후 약 1회 검사 주기 내 종료.
ACK 없음/지연, 이후 새 음성, 버퍼·송신 중 음성, 상대 끼어들기, 출력 없음,
직접 종료 및 상한 종료를 모사 매체와 제어된 시계로 검사한다.

`cd backend && uv run --locked pytest tests/calls/test_live_bridge.py tests/calls/test_manager.py tests/calls/test_native_end_call.py -q`

- [ ] Live `audio_drained`를 Realtime의 명시적 발화 완료 `played`로 바꾸지 않는다.
  기존 outcome 값과 과거 기록을 유지하고, 새 성공 확정 상태를 만들지 않는다.
- [ ] Live가 목표 달성을 보고했으나 재생 완료를 확정할 수 없는 경우 일반 업무 미완료 대신
  “요청을 마쳤다고 보고했습니다. 마지막 음성의 재생 완료는 확정하지 못했습니다.”로 설명한다.
  `playback_unconfirmed`에는 “음성 재생 확인을 기다리다 통화를 마쳤습니다.”를 표시한다.
- [ ] 모델이 보고한 요약은 출처를 표시해 유지한다. 종료 취소/사용자 직접 종료/회선 실패가
  성공 보고로 표시되지 않게 한다. 상대 거절·진행 불가와 과거 미완료 문구는 유지한다.
- [ ] 기존 API의 `end_report`를 안전하게 해석하고 누락/깨진 JSON/알 수 없는 값은
  일반 결과로 처리한다. 내부 계측값을 사용자 문구로 노출하지 않는다.
- [ ] 기존 통화 카드 레이아웃을 유지한다. 종료 결과·질문·전사·직접 종료 회귀 검사를 실행한다.

회선 실패, 과거/손상된 보고가 각각 맞는 문구를 보이고 성공으로 오인되지 않아야 한다.

## 완료 기준과 제한

연속 무음 때문에 계속 이동하던 ACK 목표가 종료를 막지 않아야 한다.
아직 재생되지 않은 유효 음성과 상대의 새 발화를 무시해 끊어서는 안 된다.
화면은 모델의 업무 보고와 음성 재생 확인 수준을 구분해야 한다.
활성도 기반 추정은 발화 완료 이벤트나 사용자의 실제 청취 확인을 대체하지 않는다.
실회선 지연 개선은 추가 실제 통화 검증 전까지 미확인으로 명시한다.
