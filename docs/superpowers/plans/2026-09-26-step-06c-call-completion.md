# 6C: 통화 종료 지연과 결과 표시 개선

**상태:** completed — 로컬 구현·자동 검사 완료. 후속 실회선 1회에서 자동 종료 성공 미확인, 사용자가 직접 종료.
**실행 방식:** 승인 후 직접 순차 구현, 실패 재현 → 수정 → 검증 → 로컬 커밋.

## 요청과 승인 범위

6B 실제 통화에서 답변과 마지막 인사를 들은 뒤 종료됐다는 사용자 확인을 받았다.
종료 대기 및 결과 판정 개선 제안에 사용자가 “개선해줘”라고 요청했다.
계획 제시 및 25초의 기산점·기존 종료 도구 동작 설명 후 사용자가 “일단 진행해줘.”라고 승인했다.
이 승인을 근거로 로컬 구현과 자동 검사를 시작한다. 25초는 종료 요청부터의 상한이며 결과 발화·인사 시간도 포함한다.
이번 계획은 로컬 구현·자동 검사까지다. 추가 실제 발신은 구현 결과를 확인한 뒤 별도로 승인받는다.

## 조사 결과

- `LiveBridge.finish`는 마지막 양방향 음성 이후 2초, 출력 큐가 완전히 비어 있음,
  `played_bytes >= sent_bytes - 640`을 모두 요구한다. 640 bytes는 현재 8kHz μ-law의 80ms다.
- 지난 실제 통화는 마지막 출력 전사 뒤에도 생성·송신량이 초당 약 8,000 bytes씩 증가했다.
  마지막 구간의 ACK는 송신량보다 약 960~1,760 bytes(120~220ms) 뒤따랐다.
  기록에는 음성 활성도·큐 길이가 없어 이후 데이터가 모두 무음이었다고 단정할 수 없다.
- 원시 음성을 사용하지 않은 로컬 재현에서, 소리가 끝났어도 무음 패킷 큐와 120ms ACK 지연을
  유지하면 현재 코드는 25초 뒤 `playback_unconfirmed`로 끝났다.
- `manager._finish`는 `played`에만 `model_reported_success`를 부여한다.
  Live의 `audio_drained`도 `incomplete`가 되고 화면은 일반 업무 미완료 문구를 보여준다.
  따라서 종료 조건과 결과 설명을 함께 다뤄야 한다.

## 선택한 방식

전체 송신량을 계속 따라잡거나 무음 큐까지 비우는 대신 **마지막 유효 음성의 끝 위치**를 추적한다.
그 위치까지 회선 재생 ACK가 도착했고, 생성 중/대기 중인 유효 음성이 없으며,
상대와 도우미의 유효 음성이 2초 이상 없을 때 기존 `audio_drained` 경로로 종료한다.
음성이 다시 생기면 대상 위치와 대기를 갱신하며, 상대가 말하면 기존 자동 종료 취소를 유지한다.

단순히 25초를 줄이거나 ACK 허용 오차를 키우면 음성 절단 위험을 가릴 수 있어 채택하지 않는다.
모델에 발화 완료 이벤트가 추가됐다는 가정도 하지 않는다. 음성 활동 기준의 추정임을 유지한다.

## 완료 기준과 제한

연속 무음 때문에 계속 이동하던 ACK 목표가 종료를 막지 않아야 한다.
아직 재생되지 않은 유효 음성과 상대의 새 발화를 무시해 끊어서는 안 된다.
화면은 모델의 업무 보고와 음성 재생 확인 수준을 구분해야 한다.
활성도 기반 추정은 발화 완료 이벤트나 사용자의 실제 청취 확인을 대체하지 않는다.
실회선 지연 개선은 추가 실제 통화 검증 전까지 미확인으로 명시한다.

## 개선 후 실회선 시험 승인

구현 완료 보고 후 사용자가 “실제 통화로 한번 확인해줘”라고 요청했다.
기존 본인 테스트 번호로 웹 채팅을 통해 1회 발신하여, 짧은 테스트 동의 응답·재확인·마지막 인사 후
자동 종료를 확인한다. 직접 종료 버튼은 정상 시험에서 누르지 않으며 자동 재발신하지 않는다.
통화 원문·번호는 이 기록에 넣지 않는다. 아래에 실제 결과를 기록한다.


### 개선 후 실회선 1회 결과

- 웹 채팅으로 승인된 본인 번호에 1회 발신했다. `gpt-live-1`과 개선 코드가 반영된 서버에서 실행했다.
- 시작 멘트·상대 응답·재확인·마지막 인사가 화면 전사로 표시됐고, 인사 전후 추가 상대 발화도 있었다.
  원문은 이 문서에 저장하지 않는다. 통화 중 종료 버튼을 누르거나 추가 발신하지 않았다.
- 사용자는 **“제가 직접 끊었어요”**라고 확인했다. 따라서 자동 종료 성공 또는 종료 지연 개선으로
  판정하지 않는다. 회선 공급자 `completed`, 로컬 `ended`, 활성 통화 0을 확인했다.
- 최종 `end_report={}`, `stop_requested=0`, `error_code=null`, `outcome=incomplete`였다.
  웹 종료 요청이 없었다는 뜻이며 전화기에서의 직접 종료 여부는 사용자 확인을 근거로 한다.
  `audio_drained`와 25초 상한 종료 중 어느 경로의 완료 기록도 없다.
- 위임 실행 1건은 applied로 끝났지만 개별 end_call 호출/취소 이력은 저장되지 않는다.
  상대 음성이 재개되면 `LiveBridge.phone`이 `ending=None`으로 지우는 경로가 있으므로
  종료 요청 취소가 유력한 조사 대상이다. 이번 기록만으로 호출 여부나 취소 시점을 확정하지 않는다.
- 다음 개선 후보: 종료 요청·취소·재판단 이력을 원문 없이 남기고, 상대 추가 발화 뒤 종료 판단을
  다시 할 수 있는 흐름을 검증한다. 이번 실회선 시험에서는 새 코드 변경이나 재발신을 하지 않았다.
