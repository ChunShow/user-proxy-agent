# 통화 결과 → Gmail 발송 확인 카드 검증

상태: completed (발송 대기 카드까지 검증; 실제 발송은 별도 승인 대기).
승인: 끼어들기 실통화 검증 완료 후 다음 단위로 “통화 결과 → Gmail 초안·확인 카드
연결 검증”을 제안했고 사용자가 “좋아 진행해줘.”라고 요청했다.

## 목적과 범위

최근 완료된 본인 테스트 통화의 결과를 같은 웹 대화에서 조회하고 연결된 본인 Google
계정을 수신자로 하는 테스트 메일 실행안 1건을 만든다. 기존 구현을 검증하는 단위다.
여기서 초안은 앱의 pending 실행안이며 Gmail 임시보관함에 저장하는 기능이 아니다.
새 전화·일정 변경 없이 진행한다. 실제 발송은 완성된 카드 내용을 보여준 뒤 별도 승인받는다.

## 작은 작업 단위와 완료 기준

1. 기존 통화 결과·연결 계정을 조회하고 메인 모델에 메일 확인 카드 생성을 요청한다.
2. 제목에 연동 테스트임을 표시하고 가상 일정임과 실제 예약/일정 등록이 아님을 담는다.
   날짜·시간·길이는 통화 기록과 대조하며 전화번호/원문 전사 등 불필요한 정보는 제외한다.
3. 웹 카드와 로컬 저장소에서 수신자·제목·본문·pending을 확인한다.
4. 새로고침 후 같은 실행안 1건이 복원되고 발송/중복 생성이 없음을 확인한다.
5. 문서와 로드맵을 갱신하고 로컬 커밋한다. 마지막 발송만 사용자에게 확인받는다.

대상 인터페이스: 기존 get_phone_call/get_connected_apps/propose_email,
웹 확인 카드와 actions 저장소. 예상 변경 파일은 이 검증 문서와 docs/roadmap.md다.
이상이 발견되면 원인을 재현하고 수정 범위를 정한다. 이번 검증은 실제 웹·모델을 사용하며
실제 Gmail 발송·수신까지 검증했다고 표현하지 않는다. 사용자 데이터는 커밋하지 않는다.

## 결과

- 최근 본인 실통화가 있는 웹 대화에서 실제 메인 모델에 후속 메일 확인 카드를 요청했다.
  앱에 메일 실행안이 정확히 1건 생성됐다. 기존 구현 변경은 필요하지 않았다.
- 수신자는 연결된 계정과 같으며 제목에 연동 테스트를 표시했다. 본문은 원 통화의
  날짜·한국 시각·길이와 일치하고, 가상 테스트·일정 미등록·회신 불필요를 명시했다.
  전화번호와 원문 전사는 포함하지 않았다. 개인 주소와 본문 원문은 문서에 저장하지 않는다.
- 웹 카드와 SQLite payload를 대조했다. pending, version 1, 빈 실행 결과를 확인했다.
- 새로고침 뒤 같은 ID의 카드 1건과 동일 내용·발송 확인 버튼이 복원됐다.
  재조회에서도 pending/version 1/빈 결과를 유지했다. 실제 발송은 하지 않았다.
- `uv run pytest tests/actions/test_actions.py -q`: 7개 통과.
  내용·수신자 일치·실행안 개수에 대한 로컬 단언 검사와 git diff --check 통과.
- 이번 증거는 실제 웹/모델/앱 실행안 저장에 해당한다. Google 발송·수신 검증은
  카드 내용을 사용자에게 제시하고 승인을 받은 뒤 별도 진행한다. 카드는 생성 후 30분 만료다.
