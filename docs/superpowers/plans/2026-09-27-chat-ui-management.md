# 채팅 화면 정리와 대화 관리

상태: completed.

사용자 요청: 마크다운 표시 수정에 이어 “불필요한 화면 예시”와 응답마다 반복되는 이름 제거,
대화 제목 설정·삭제, 첫 답변 후 자동 제목 생성, 새 대화 아이콘 개선을 직접 요청했다.
이후 화면 하단의 회색 공백 제거도 추가 요청했다. 이 구체적인 수정 범위 안에서 진행한다.

기존 흑백 채팅 스타일을 유지한다. 예시 화면 진입·기능을 제거하고 새 대화는 사각형 안 연필
아이콘으로 표시한다. 답변의 발화자 구분은 스크린리더용으로 남긴다. 화면 밖 여백은
실측한 문서 높이 넘침(화면 851px, 문서 1001px)을 해결하고 본문·목록 내부 스크롤을 유지한다.

대화 행의 더보기에서 이름 변경/삭제를 제공한다. 삭제는 확인 후 휴지통으로 이동하는 방식이며
삭제한 대화 목록에서 복원할 수 있다. 진행 중 응답·통화·외부 실행이 있으면 삭제를 거절한다.
실제 Google 일정·메일은 삭제하지 않는다. 기존 대화 데이터와 통화 기록은 보존한다.

첫 정상 답변 이후 첫 질문/답변만 기존 메인 모델에 보내 짧은 한국어 제목을 생성한다.
도구 없는 별도 요청이며 저장소의 원자적 상태 변경으로 중복 생성을 막는다. 실패 시 첫 질문
축약 제목을 유지하고 응답 자체는 성공으로 유지한다. 수동 제목은 늦게 도착한 자동 제목으로
덮어쓰지 않는다. 기존 대화 제목은 일괄 변경하지 않는다.

작업: 저장/API/소유권/경합 회귀 테스트 → 구현 → 웹 상태/메뉴/확인창 → 예시 제거와 CSS 정리 →
전체 자동 검사와 실제 브라우저 데스크톱/모바일 검증 → 문서/로컬 커밋. 실제 발신·메일·일정 변경
없이 합성 대화로 제목 생성과 관리 동작을 검증한다.


구현·검증 결과:
- 화면 예시의 진입점/전용 컴포넌트/상태 제거. 이전 preview URL도 일반 채팅으로 정리한다.
  반복 발화자 이름은 화면에서 숨기고 스크린리더에서는 '나/도우미'로 구분한다.
- 대화 행의 더보기 → 이름 변경/삭제. 삭제 확인, 목록 제외, 삭제한 대화에서 복원, 새로고침
  뒤 제목/메시지 유지를 실제 브라우저의 별도 DB/쿠키를 사용해 확인했다. 모바일에서도 이름
  변경 창과 Escape 취소/포커스 복귀를 확인했다. 실제 개인 대화는 변경하지 않았다.
- 첫 완료 이벤트 후 웹에서 제목 생성을 요청하며, 저장소가 첫 정상 질문/답변 쌍을 한 번만
  선점한다. 기존 모델의 문자열 및 Responses 텍스트 블록 배열을 모두 지원한다.
  12초 제한/무재시도, 실패 시 질문 축약 제목 유지. 수동 제목이 자동 응답보다 우선한다.
  실제 API 합성 질문은 '서울대학교 치과병원 진료시간' 제목을 반환했다.
- 삭제한 대화의 캐시된 Google 확인 카드도 실행을 거절한다. 진행 중 답변/통화/Google 실행이
  있으면 삭제 불가. 삭제는 DB 영구 제거가 아니라 복원 가능한 휴지통 이동이다.
- 하단 여백: 절대 배치된 숨김 텍스트의 기준을 메시지 안으로 제한하고 루트 밖 스크롤을 제거.
  실제 화면 1745×851에서 문서 크기 동일, 모바일 유효 뷰포트 355×767에서 문서 크기 동일.
- ./scripts/check.sh: backend 325개, 웹 42개, Ruff/TypeScript/ESLint/빌드 통과.
  기존 예시 전용 E2E 사양은 제거하고 대화 관리 사양을 추가했다. Playwright E2E 전체 실행은
  하지 않았으며 위 인터랙션 검증은 CUA 브라우저 조작으로 수행했다.
- var/ui-polish-before.sqlite3 비공개 백업 후 로컬 재시작. 기존 저장 테이블 6종의 모든 기존
  열/행이 동일함을 확인했다. 실제 발신/Google 쓰기 없음. 격리 테스트 서버는 종료한다.
