# 2단계 수정: user proxy agent

상태: completed

## 요청과 승인 범위

2026-09-25, 2단계 완료 후 사용자가 다음과 같이 수정을 요청했다.

> 좀 더 에이전트 스럽지 않게 디자인을 수정해줄래? user proxy agent를 이름으로 하고,
> 에이전트 스럽지 않은 프론트 엔드 디자인에 필요한 스킬이 있다면 찾아서 설치한 다음에 진행해줘.

이 요청에 따라 기존 2단계의 시각 디자인과 표시 이름을 수정한다. 새 단계나 기능을 추가하지 않는다.
채팅 입력, 모바일 탐색, 통화 상태 예시, 듣기·추가 지시·종료·내역 조작은 유지한다.

## 방향과 작업 단위

- 표시 이름과 브라우저 제목을 정확히 `user proxy agent`로 통일한다.
- 캐릭터 아바타, 장식 로고, 슬로건과 소개 문구를 걷어낸다.
- 흰 바탕, 중립 회색, 검은 글자와 기본 시스템 글꼴을 사용한다. 초록·빨강은 연결·종료 상태에 한정한다.
- 헤더·탐색 영역을 작고 단순하게 정돈하고 메시지의 읽기 흐름을 우선한다.
- 통화 카드는 그림자 없이 한 겹의 회색 테두리로 구분하고, 중복된 카드 소개 줄을 없앤다.
- 입력창·버튼의 과한 둥글기와 강조색을 줄이고 키보드 포커스와 44px 터치 영역을 유지한다.

파일: `web/src/chat/{ChatView,Composer,MessageList,CallCard}.tsx`, `chat.css`,
`web/src/styles.css`, `web/index.html`, README, 제품·로드맵 문서 및 화면 검증 이미지.
API·상태 모델·저장 방식·통화 연동의 인터페이스 변경은 없다.

## 검증과 완료 기준

기존 입력·IME·탐색·통화 조작 및 4개 viewport E2E 14개, 타입 검사·lint·빌드를 실행한다.
데스크톱과 모바일의 빈 대화·통화 화면을 실제 Chrome으로 캡처해 시각적으로 확인한다.
Impeccable detector는 완성된 변경 파일에 한 번 실행하고 관련 결과를 검토한다.
검증 후 변경 파일과 기록을 로컬 Git에 커밋한다.

## 결과

- 표시 이름·탭 제목을 `user proxy agent`로 변경했다. 내부 API 식별자는 유지했다.
- 아바타·장식 로고·슬로건·카드 소개 줄을 제거했다. 사이드바 접기 버튼을 상단에 배치했다.
- 중립 색상과 여백으로 대화를 구분하고, 사용자 메시지만 옅은 배경으로 표시한다.
  입력창과 통화 카드는 그림자 없는 테두리로 단순화했다.
- `./scripts/check.sh`: backend 3개, web API 8개 통과. Ruff·TypeScript·ESLint·빌드 통과.
- `env -u NO_COLOR PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`: 기존 14개 모두 통과.
  1440×900, 768×1024, 390×844, 320×568 레이아웃과 기존 조작을 검증했다.
- 실제 개발 서버에 연결한 Chrome에서 데스크톱·모바일의 빈 대화와 통화 화면 4개를
  캡처·육안 검토했다. 제목, 여백, 버튼 구분, 모바일 입력창과 스크롤이 정상이다.
- 추가 브라우저 확인: 접은 탐색 영역에서 화면 전환·다시 펼치기 정상,
  320px 화면에서 제품명과 서버 상태가 겹치지 않음.
- 주요 보조 글자·상태 색 대비는 흰색/실제 회색 배경에서 4.5:1 이상이다.
- Impeccable detector: 변경 UI 7개 파일에서 `[]` (탐지 항목 없음).
- 새 스킬은 사용자 영역에 설치했다. 이번 작업에서는 직접 읽어 적용했고,
  이후 턴부터 스킬 목록에서 자동으로 사용할 수 있다.
- 실제 모델 응답·전화·음성 재생은 이번 수정의 검증 대상이 아니며 기존 화면 예시 범위를 유지한다.

화면 기록: `docs/verification/step-02-refined-{desktop,mobile}-{empty,call}.png`.
이전 `step-02-desktop.png`와 `step-02-mobile.png`는 수정 전 비교 기록으로 보존한다.

## 후속 수정: 자연스러운 시작과 조작 흐름

상태: completed

같은 대화에서 사용자가 “좀 더 자연스럽게 개선해줘. 세련되면서도 간결하게. UI UX에 신경써서”라고
요청했다. 2단계 디자인의 후속 수정으로 진행하며 새 서비스 연동은 추가하지 않는다.

- 빈 화면의 안내와 입력창을 가까이 묶는다. 첫 메시지 이후에는 입력창이 하단에 놓인다.
  기존 textarea를 유지해 초안·포커스·한글 조합이 보존되도록 한다.
- 제품명·메시지·보조 문구의 크기와 줄 간격을 정돈한다. 전체적인 흰색·회색 방향을 유지한다.
- 통화 예시 안내와 상태 선택을 한 영역에 묶고, 통화 카드의 목적·상태·조작 우선순위를 정리한다.
- 탐색에서 실제 대화와 화면 예시를 떨어뜨려 두고, 버튼의 hover·focus·pressed 상태를 정돈한다.
- 입력 영역의 여백·안내 문구를 정리하고, 작은 화면과 낮은 화면에서도 조작이 보이도록 한다.

대상: ChatView, Composer, App의 예시 안내 배치, chat.css, UI 회귀 테스트와 화면 기록.
기존 14개 E2E에 시작 화면과 대화 진입 시 배치·포커스 검증을 더한다.
데스크톱·모바일 캡처와 타입 검사·lint·빌드를 확인한 뒤 작은 단위로 커밋한다.

### 후속 수정 검증

- 먼저 시작 화면의 안내–입력창 간격과 메시지 입력 후 하단 배치·포커스를 검사하는
  테스트를 작성했다. 기존 화면에서 데스크톱·모바일 간격이 266px/257px로 실패하는 것을 확인했다.
- 구현 후 전체 E2E 17개 통과. 320×420의 낮은 화면을 포함한 신규 3개 테스트도 통과했다.
- TypeScript·ESLint·프로덕션 빌드 통과. 마지막 문구 수정 후 관련 3개 테스트와 빌드를 재확인했다.
- 실제 로컬 서버의 1440×900·390×844 시작/통화 화면 4개를 캡처하고 검토했다.
  긴 여러 줄 초안에서도 입력 영역이 화면 안에 유지되는 것을 확인했다.
- 44px 조작 영역, 키보드 탐색·한글 조합, 전사 펼침·통화 예시 전환은 기존 E2E로 검증했다.
  입력 중 포커스는 입력창 전체의 테두리로 표시하고, 다른 버튼의 포커스 링은 유지한다.
- Impeccable detector 결과 `[]`. 외부 서비스 호출·API·데이터 저장 방식의 변경은 없다.
- `step-02-refined-*.png` 4개를 최신 화면으로 갱신했다. 이전 버전은 Git 기록에서 확인할 수 있다.
