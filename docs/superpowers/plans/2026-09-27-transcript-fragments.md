# 교차 도착하는 통화 전사 조각 표시 수정

상태: completed. 사용자가 '여보/세요', '괜찮/아요'와 도우미 전사가 교차해 별도 행으로
표시되는 사례를 제시하며 수정을 요청했다. 기존 표시 결함의 제한된 수정으로 진행한다.

원인: Live 원문에는 start_ms/end_ms가 있으나 transcriptRows는 인접 이벤트의 화자와
DB 도착 시각(2초)만 사용한다. 중간에 다른 화자의 전사가 오면 같은 단어도 새 행이 된다.
실제 저장 이벤트에서 200~400ms 간격의 이어지는 토큰 사이에 반대 화자 토큰이 끼는 것을 확인.

동일 화자별 발화 시각으로 짧게 이어지는 조각을 묶고 첫 조각 기준 행 순서를 유지한다.
다른 화자의 말은 별도 행으로 보존하며, 문장 종료 후 상대 발화 또는 긴 공백은 새 행으로 둔다.
시각이 없거나 유효하지 않은 과거 데이터는 보수적으로 기존 인접 조각 결합을 유지한다.
전사 단어나 문장, 원본 DB, 통화 모델·음성·종료 판단은 변경하지 않는다.
앞쪽 행에 뒤늦게 조각이 추가돼도 새 내용/자동 스크롤 갱신이 감지되도록 함께 수정한다.

교차 조각/긴 공백/별도 응답/잘못된 시각/도착 지연/페이지 중복 회귀를 먼저 재현한 뒤
웹 검사·타입·린트·빌드와 실제 저장 전사 화면을 검증한다. 실제 발신 없이 로컬 커밋한다.


검증 결과: 교차 조각과 전송 지연 회귀 2개 실패를 재현한 뒤 수정했다. 시각이 있는 조각은
화자별로 추적하며 교차 도착 시 800ms, 동일 화자 연속 시 2000ms 내 음성 공백을 묶는다.
문장 종료 후 다른 화자가 발화한 경우에는 별도 행을 유지한다. 시각 없는 데이터는 기존의
인접 화자/도착 시각 규칙을 유지한다. 실제 발화 경계를 보증하는 모델 turn ID는 없으므로
짧은 연속 조각의 시간 기반 표시 규칙이며 원문을 재작성하지 않는다.

실제 사용자가 지적한 저장 전사에서 '여보세요', '괜찮아요', 인사/질문이 9개 행으로 정상
표시됐다. 화자별 전체 글자를 전후 비교해 누락/순서 변경 없음을 확인했다. 브라우저에서도
해당 통화를 열어 동일 결과를 확인했다. 앞쪽 행의 늦은 갱신과 페이지 중복 검사도 통과했다.
