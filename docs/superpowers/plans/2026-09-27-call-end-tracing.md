# 자동 종료 단계 추적과 실회선 검증

상태: completed — 실제 청취 및 자동 종료 사용자 확인 완료

## 승인과 범위

자동 종료 기록 보강 → 모사 테스트 → 본인 번호 실통화 순서를 제안했고 사용자가
“좋아 진행해줘.”로 승인했다. 이번 회선은 기존 본인 시험 번호(끝자리 9615) 1회이며,
간단한 통화 가능 여부 확인과 답 재확인 후 인사·자동 종료만 수행한다.
실제 예약/메일/Google 조회는 하지 않는다. 추가 발신은 자동으로 반복하지 않는다.

## 작은 작업 단위

1. 현재 end_call 도구 → 최종 답변 → Live 인사 명령 ACK → 재생 판정 →
   ClawOps hangup 요청/응답/종료 확인의 경계를 명시적으로 기록한다.
2. SQLite 이벤트와 Langfuse 원 요청 trace에 같은 단계 이름을 연결한다.
   허용한 이유 코드·상태·숫자 지표만 기록하며 전사/음성/전화번호/요약은 보내지 않는다.
3. 도구 호출 이후 취소/오류, 새 발화로 오래된 판단 폐기, 직접 종료, 이미 종료된 회선,
   hangup 실패/미확인을 모사한다. 수집 실패가 회선 제어를 방해하지 않아야 한다.
4. 승인된 본인 번호 1회로 웹에서 발신하고 사용자의 마지막 인사 청취·종료 방식을 확인한다.
   자동 종료 실패가 재현되면 새 기록으로 원인을 좁히고 승인 범위의 회귀 수정만 수행한다.

## 파일·완료 기준

observability.py, calls/live_store.py, delegation.py, live_bridge.py, manager.py와 관련 테스트.
모사 검증과 실제 검증을 분리하고, 자동 종료/직접 종료/회선 종료만 확인된 경우를 구별한다.
기록 개선만으로 기존 종료 알고리즘이 잘못됐다고 가정하거나 완료 표시를 높이지 않는다.

## 구현·검증 결과

- 종료 도구 뒤 최종 답변 준비/취소, Live 인사 명령 시작/ACK/실패, 회선 정리 진입 이유,
  carrier hangup 요청/반환/실패와 최종 상태 확인을 기록한다. 기존 종료 판단 기준은 유지했다.
- SQLite의 종료 단계 이벤트를 Langfuse의 같은 원 요청 trace에 추가한다. 이벤트 이름,
  이유/상태 enum, 숫자 계측만 허용한다. 음성·전사·요약·연락처 원문은 보내지 않는다.
- 전체 backend 264개 및 Ruff 통과. 실제 carrier terminal 코드 허용 목록 검사를 추가한
  최종 종료 추적 테스트 9개도 통과했다(총 265개 테스트 중 기존 264개와 신규 1개 검증).
- 새 서버를 적용하고 ClawOps/Live preflight 정상 후 승인된 본인 번호에 웹에서 1회 발신했다.
- 실통화에서 end_call 도구 → 최종 답변 준비 → 인사 명령 ACK(384ms) →
  audio_drained(종료 요청 후 12,125ms) → media 경로 종료 → carrier completed를 확인했다.
  유효 음성 끝 248,800 bytes까지의 ACK를 충족했고 pending voice 0, 무음 출력 약 2초였다.
  이는 음성 활동+ACK 기반 추정이며 문장별 실제 청취 확정과는 다르다.
- `_finish`의 첫 상태 조회에서 이미 completed여서 별도 hangup API 요청은 없었다.
  애플리케이션의 재생 완료 후 미디어 연결 정리와 회선 종료가 연이어 발생했다.
  명시적 hangup API 성공으로 설명하지 않는다. 웹 직접 종료 요청은 0건이다.
- Langfuse에서 원 요청의 main-chat/call-delegation, 모델/도구, 종료 단계 총 16개 관측을
  재조회했다. SQLite의 종료 단계 8개와 일치하고 입력/출력 원문은 없었다.
- 새로고침 후 종료 기록 복원, 활성 통화 0건. 실제 예약/Google 조회/메일 발송 없음.

## 남은 확인과 발견

- 사용자가 “직접 끊지 않았고, 추가 설명 후 자동으로 끊겼어요”로 실제 청취 및
  자동 종료를 확인했다. 이번 시험에서는 종료 도구와 회선 종료가 동작했다.
- 전사에는 첫 인사 뒤 업무 결과를 3인칭으로 다시 설명하는 추가 발화가 나타났다.
  Live의 자율 인사 뒤 백엔드 최종 답변을 다시 읽도록 하는 기존 지시가 중복 발화의
  가능 경로다. 종료 도구 미호출이나 고정 25초 타임아웃 문제로 오인하지 않는다.
  본 단계에서는 실제 기록으로 구간을 식별했으며 대화 정책 변경·추가 발신은 하지 않았다.
