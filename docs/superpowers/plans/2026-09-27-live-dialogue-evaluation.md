# 한국어 다중 발화 음성 평가와 대화 흐름 개선

상태: completed (평가와 확인된 제어 결함 수정; 전체 대화 품질 해결은 미완료)
승인: 이전 턴에서 제안한 프롬프트 재정리/다중 발화 평가에 대해 사용자가
“진행해줘. 음성 평가도 만들어서 진행해줘.”라고 지시했다.

## 조사 근거와 범위

실제 제보에서는 현재 활동 답을 인식하고도 이유 질문 뒤 원래 질문을 반복했다.
반복 시점에는 백엔드 위임이 없었으며, 나중에는 활동 답을 기억해 되풀이했다.
내부 모델 원인을 확정하지 않고, 과업 질문 재시작과 최신 발언 처리 정책을 평가한다.
기존 Live 프롬프트를 baseline으로 고정하고 짧은 대화 흐름 중심 candidate와 비교한다.
복잡한 상태 관리자나 매 턴 Sol 위임은 이번에 성급하게 추가하지 않는다.

## 구현과 평가

- 명시적으로 --run을 지정해야 비용이 발생하는 전화 없는 평가 CLI를 만든다.
- 로컬 Yuna 합성 음성을 PCMU 8kHz로 입력한다. 상대 음성과 모델 실제 음성 출력을 저장한다.
- 프로덕션 LiveAudioSession/LiveBridge/DelegationCoordinator와 실제 설정의 backend 모델을
  사용한다. 평가 전용 SQLite와 가상 media/ACK만 사용하며 전화망/Gmail/Calendar는 연결하지 않는다.
- 현재 활동→이유→기억 확인, 통화 가능 시간 정정, 거절, 선호 없음의 5개 시나리오(제보 문구 그대로의 반복 지적 사례 포함)를 각
  baseline/candidate 2회씩 비교한다. 최대 동시 세션 2개, 각 세션 최대 70초로 제한한다.
- 실제 수신 음성/전사, 시나리오 입력 완료 여부, 위임/종료 요청, 재질문 후보를 기록한다.
  정규식은 검토 후보 표시일 뿐 자연스러움의 자동 합격 판정이 아니다. 발화 내용을 직접 검토한다.
- 답을 못 듣거나 세션이 일찍 닫히면 성공으로 처리하지 않는다. mock ACK 결과를 실제 회선 종료
  또는 사용자 청감 검증으로 표현하지 않는다.
- 회귀 검사와 비교 근거가 개선을 뒷받침할 때만 candidate를 배포 프롬프트에 적용한다.

산출물: scripts/check_live_dialogue.py, 사례/판독 유틸리티와 테스트, 프롬프트 fixture,
ignored var/live-dialogue/<label>/ 아래 음성·전사·이벤트·설정. 완료 시 결과표와 실행법을 기록한다.
공식 근거: https://developers.openai.com/api/docs/guides/live-prompting


## 평가 중 확인한 제어 문제

candidate-v2 activity_reason-1에서 21.9초에 종료 안내 지시가 전달된 뒤 22.86초에 상대의 새
질문이 시작됐다. 서버는 ending만 취소하고 모델의 종료 지시는 갱신하지 않아 이전 설명/인사가
최신 질문과 겹쳤다. 원 제보의 무위임 재질문과는 별개로, 자연스러운 후속 대화에 영향을 주는
결함이다. 음성 입력을 막지 않는 별도 작업에서 대기 음성을 비우고 모델에 종료 취소/대화 재개를
전달한다. 새 종료 결정과 직렬화하며 이미 새 결정이 있으면 이전 취소는 생략한다.
수정 전 실패 테스트를 확인했다. 프롬프트 수정안은 평가 결과가 부족하면 적용하지 않는다.

## 결과

기존/수정안/두 번째 수정안 각 10회와 제어 수정 후 4회, 총 34개 실제 API 음성 세션을
실행했다. 두 프롬프트 수정안은 불필요한 재질문 등의 문제가 있어 채택하지 않았다.
종료 취소가 모델에 전달되지 않는 제어 결함을 수정하고 별도 종료 후 재질문 2회에서
대화 재개를 확인했다. 관련 자동 검사 229개와 Ruff 통과. 실제 발신/Google 실행 없음.
음성/전사 청취 보고서를 생성했다. 전체 품질 개선 여부는 미확정이며 결과와 제한은
[평가 기록](../../evaluations/2026-09-27-korean-dialogue.md)에 정리했다.
