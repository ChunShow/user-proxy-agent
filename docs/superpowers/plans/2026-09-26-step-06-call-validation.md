# 6A 후속: 발신 요청·회선 종료 분류 수정과 실제 답변 전달 검증

상태: in_progress

## 승인과 범위

직전 진행 현황에서 제안한 “두 오류를 정리하고, 실제 통화에서 웹 답변 → 음성 전달 → 종료까지
검증하는 작은 작업”에 사용자가 “좋아 진행해줘.”라고 승인했다. 해당 범위를 구체화한다.
새 기능 단계인 6B나 청취·앱 연결은 포함하지 않는다. 현재 기능 브랜치에서 직접 작업한다.

## 목적과 원인

- `requested_number`가 전화/통화 뒤 임의의 16자 안에 부정어가 있으면 전체 요청을 거절한다.
  발신 요청 뒤의 별도 조건인 “통화 가능한지는 추측하지”도 발신 금지로 잘못 판정한다.
- ClawOps에서 응답 없이 종료되면 미디어 연결 대기가 예외로 끝나 `call_audio_failed`가 되고,
  최종 회선 조회의 `no_answer`를 저장/표시에 반영하지 않는다.

## 작은 작업 단위

1. 실패를 재현하는 테스트부터 추가한다. 부가 조건을 포함한 명시적 발신은 허용하되
   직접적인 발신 금지, 번호 부재, 불명확한 요청은 계속 거절한다.
2. `backend/src/agent_service/calls/manager.py`의 부정 발신 표현을 전화 행동에 한정한다.
   최종 회선 조회가 no_answer/busy/failed/canceled이면 대응하는 원인을 기록한다.
   정상 연결 뒤 음성 오류는 유지한다. 중복 방지·종료 확인·재시도 정책은 유지한다.
3. `calls/tools.py`의 저장된 통화 문맥에도 원인을 포함하고, `PhoneCallCard.tsx`에서
   사용자가 알 수 있는 짧은 문구로 표시한다. API 형태와 DB 스키마는 바꾸지 않으며
   error_code 값만 추가한다. 기존 카드의 레이아웃/스타일을 유지하는 문구 수정이다.
4. 관련 백엔드 회귀 검사와 웹 통화 카드 E2E, 정적 검사·빌드를 실행한다.
5. 활성 회선이 없는 상태에서 서버를 갱신하고, 기존 본인 테스트 번호에 웹으로 한 번 발신한다.
   제안 시간 → 웹 질문 → 테스트 답변 → Live 반환 전사/음성 송신 → 회선 종료를 확인한다.
   답변은 사용자가 직접 입력하거나, 테스트용 가상 답변임을 밝히고 대신 입력한다.
   응답 없는 경우 자동 재발신하지 않는다. 실제 예약·일정 변경은 하지 않는다.

## 검증과 완료 기준

- `backend/tests/calls/test_manager.py`: 부정어 오탐 재현과 명시적 금지 보존,
  미디어 연결 종료/초기 회선 종료에서 정확한 원인, 일반 음성 실패 보존, 발신 1회.
- `web/e2e/phone-calls.spec.ts`: 실제 카드가 부재중/통화 중/회선 실패를 구분하며
  종료된 회선에 재발신/종료 버튼을 추가하지 않는지 확인한다.
- 실통화는 회선 완료와 업무 성공을 구분한다. Live 명령 ACK, 생성 전사,
  음성 송신/재생 확인, 사용자의 청취 평가는 서로 다른 근거로 기록한다.
- 자동 검사 결과와 실제 확인 범위·미확인 사항을 기록하고 작은 단위로 로컬 커밋한다.
- 키·번호·통화 원문은 Git에 포함하지 않는다.
