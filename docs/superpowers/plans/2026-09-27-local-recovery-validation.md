# 로컬 재시작·연결 오류·중복 실행 방지 점검

상태: completed. 승인: 재시작/재접속/작업 오류/중복 실행 방지를 실제 발신이나 외부 쓰기
없이 점검하자는 제안에 사용자가 “진행해줘.”라고 승인했다.

## 범위와 작업 순서

1. 기존 복구 경로와 회귀 검사를 검토하고 자격증명을 배제한 전체 검사로 현재 기준을 확인한다.
   채팅 부분 실패/재시도, 발신 결과 불명확, Google 응답 유실, 실행 중 재시작, 결과 보고 복구를 다룬다.
2. 현재 DB의 활성 회선·응답·실행 작업이 없는지 확인한다. SQLite 백업과 핵심 레코드
   요약 해시를 ignored var에 저장하고, 정상 재시작 후 대화/통화/실행안/결과가 유지됨을 대조한다.
3. 웹은 유지한 채 백엔드 응답을 잠시 중지하여 실제 브라우저의 시간초과·재시도 안내를 확인한다.
   백엔드는 반드시 재개하고 기존 대화/완료 카드의 재접속 복원을 확인한다. 모델 요청은 보내지 않는다.
4. 문제가 재현되면 원인에 맞는 실패 테스트부터 추가해 수정한다. 단순 검증을 위해 코드를 바꾸지 않는다.
5. 실행·종료·복구 지침과 검증 한계를 README/계획/로드맵에 정리하고 로컬 커밋한다.

## 완료 기준

데이터/완료 상태 보존, 중단 작업의 명확한 상태, 복구 시 재발신·재전송 없음, 브라우저 오류에서
수동 재조회로 정상 복구를 확인한다. 실제 기록/브라우저 검증과 임시 DB/모사 공급자 검증을 구분한다.
실제 통화 중 서버를 종료하거나 실제 Google 작업 중 장애를 일으키지 않는다.
예상 변경 파일은 문서이며, 발견한 결함의 코드/회귀 테스트만 추가한다.

## 결과

- `./scripts/check.sh`: backend 313개, web 36개, Ruff/TypeScript/ESLint/production build 통과.
  실제 공급자 호출 없이 채팅 부분 실패/중단 복원·재시도, 동일 요청 중복 방지, 통화 재시작
  재발신 없음, Google 응답 유실/재시작 unknown 및 재전송 없음, 결과 보고 중단 복구를 검증했다.
- 운영 DB에서 활성 통화/채팅 응답/외부 실행/미완료 결과 보고 0건을 확인했다.
  ignored `var/recovery-2026-09-27/`에 SQLite backup API로 0600 백업과 비교 해시를 저장했다.
  백업/운영 DB의 integrity_check가 ok였다. 개인정보 본문/자격증명은 출력·커밋하지 않았다.
- 웹을 켠 채 백엔드 프로세스만 SIGSTOP으로 일시 정지했다. 별도 45초 자동 재개 장치를
  두고, 관찰 후 직접 SIGCONT로 복구했다. 서버 상태는 시간초과 후 실패, 대화/목록은
  조회 실패와 재조회 버튼을 표시했다. 무한 로딩이 남지 않았다.
- 서버 재개 후 대화/목록 재조회와 서버 확인 버튼으로 복구했다. 원래 통화 종료 카드와
  메일 발송 완료 카드가 표시됐다. 서버 상태·목록·본문의 재조회는 독립이라는 점을 안내에 명시했다.
- dev 실행기를 정상 종료/재시작하고 웹을 새로고침했다. 같은 대화·통화·완료 카드가 복원됐다.
  대화 23, 메시지 89, 응답 실행 43, 통화 16, 실행안 4, 결과 보고 5건의 전체 행 해시가
  전후 일치했다. 새 발신/메일/일정 실행이나 모델 요청은 만들지 않았다.
- 새 제품 결함은 재현되지 않아 코드 수정은 하지 않았다. README에 연결한
  `docs/local-recovery.md`에 시작/종료, 오류 재조회, 미확인 결과, 백업/복원 제한을 정리했다.

브라우저 E2E 전체를 새로 실행한 것은 아니며 실제 브라우저의 이번 복구 경로만 확인했다.
사용 중 회선/Google 작업에 장애를 주입하지 않았으므로 해당 경합의 증거는 모사 회귀 검사다.
