# Google 실제 조회 검증과 응답 완료 오류 수정 계획

검증 상태: 수정 후 실제 조회·답변 생성·웹 완료·새로고침 복원 확인.
수정 계획 상태: completed.
수정 승인: 위 계획을 제시한 뒤 사용자가 “진행해줘.”라고 명시적으로 승인했다.

## 승인된 검증

사용자는 Google 계정 연결 후, 일정·메일 조회를 먼저 검증하자는 제안에
2026-09-27 “좋아 실행해줘.”라고 승인했다. 실제 웹의 새 대화에서 다음을 요청했다.

1. 이번 주 Google Calendar 일정을 한국 시간으로 정리.
2. 최근 받은 Gmail 메일 5개의 발신자·제목·시각·핵심 내용 요약.

일정 생성·메일 발송·전화 발신은 하지 않았다. 계정 주소, 메일 내용, 토큰과 비밀키는 이 문서에 남기지 않는다.

## 실제 결과와 원인

- OAuth 연결과 Calendar/Gmail 조회·쓰기 권한을 확인했다. 실제 쓰기 기능은 검증하지 않았다.
- Calendar 답변은 2026-09-21 00:00부터 09-28 00:00까지 KST 기준 일정 0건이었다.
  별도 Google API 조회에서도 0건이고 페이지 잘림이 없음을 확인했다.
- Gmail은 받은편지함의 최근 5건을 요약했다. Google API에서 독립 조회한 최근 5건의 제목이
  웹 답변과 모두 일치했다. 모든 본문 요약의 의미적 정확성까지 독립 검증한 것은 아니다.
- 두 웹 답변 모두 텍스트 생성 뒤 `provider_unavailable`로 저장되고 재시도 안내가 표시됐다.
- 같은 `SavedReply.events()` 경로를 실제 모델·Google 조회 도구와 기록하지 않는 진단용 저장소로
  실행해 `GraphRecursionError: Recursion limit of 12 reached without hitting a stop condition`을 재현했다.
- 발생 위치: `chat/routes.py`의 `pending.result()` → `chat/runtime.py`의 `stream_reply` →
  `stream_agent` → LangGraph `astream`. `stream_agent`가 실행 한도를 12로 고정하고 있다.
  `error_code()`는 이를 공급자 오류로 분류한다.
- 별도 에이전트 실행은 완료되기도 했다. 도구 호출 순서·내부 실행 경로에 따라 발생하므로
  Google 연결 오류나 항상 실패하는 조회 기능으로 해석하지 않는다.

## 다음 수정 제안

목적: 정상적인 여러 단계 조회를 완료하고 실행 한도 초과는 정확하게 알린다.

범위와 파일:

- `backend/src/agent_service/chat/runtime.py`: 그래프 단계 한도를 명명된 상수로 관리하고
  정상적인 여러 도구 조회가 가능한 유한한 한도(우선 64)를 적용한다.
- `backend/src/agent_service/chat/routes.py`: 그래프 한도 초과를 별도 오류 코드로 분류하고
  부분 응답을 성공으로 바꾸지 않는다.
- 웹의 오류 표시 경로: 새 코드가 공급자 연결 실패로 표시되지 않게 필요한 최소 변경.
- 관련 backend/web 테스트, 이 계획과 로드맵의 실제 검증 상태 갱신.

작업 순서:

1. 실제 DeepAgents 그래프와 모사 모델·도구를 사용해 여러 단계 조회 후 완료되는 회귀 검사를 작성한다.
   기존 한도에서 실패하고 수정 후 완료되어야 한다.
2. 계속 도구를 요청하는 그래프는 유한한 한도에서 종료되며 별도 오류로 표시되는지 검사한다.
3. 한도와 오류 분류를 최소 변경하고 스트림 중단·시간 초과·부분 응답 처리를 회귀 검사한다.
4. 관련 검사 통과 후 활성 통화·실행 작업을 확인하고 개발 서버를 재시작한다.
5. 웹에서 같은 두 조회 요청을 다시 실행해 성공 종료와 새로고침 후 완료 상태를 확인한다.
   실제 등록·발송·전화는 수행하지 않는다.

완료 기준: 일정/메일 웹 요청이 오류 없이 completed로 저장되고, 반복 실행 한도 초과는
실패로 보존되며 원인이 구분된다. 개인정보를 Git에 남기지 않고 변경·검증 결과를 커밋한다.

## 수정 및 최종 검증

- 그래프 실행 한도를 12에서 64로 늘렸다. 도구뿐 아니라 미들웨어 실행도 단계 수에 포함된다.
  무한 반복 제한과 기존 120초 응답 제한은 유지한다.
- 한도 초과는 `agent_step_limit`으로 구분하고, 요청 범위를 줄여 다시 질문하도록 안내한다.
  부분 응답은 failed로 보존하며 완료로 바꾸지 않는다. 저장된 대화에도 같은 오류·재시도 정책을
  적용하기 위해 `storage.py`의 공개 메시지 변환도 수정했다.
- 수정 전 실제 DeepAgents 그래프의 6회 연속 조회 테스트에서 GraphRecursionError가 발생했고,
  API 오류 분류 및 웹 재시도 정책 테스트도 실패하는 것을 확인했다.
- 수정 후 관련 backend **50 passed**:
  `AGENT_SERVICE_ENV_FILE=/dev/null uv run pytest -q tests/test_chat_runtime.py tests/test_chat_api.py tests/integrations tests/test_conversations.py`
  최초 실행에서는 실제 `.env`의 Google 설정 때문에 미설정 상태를 가정한 기존 테스트 1개가
  실패했다. 테스트 실행에만 빈 설정 경로를 지정했고 실제 `.env`는 변경하지 않았다.
- 웹 **26 passed** (`npm test`), TypeScript·ESLint 및 변경 Python 파일 Ruff 검사 통과.
  계속 도구를 요청하는 그래프는 유한한 한도에서 실패하고, 오류 응답·부분 본문·실패 상태가
  저장/복원되는 것도 검사했다. 전체 프로젝트 E2E를 재실행한 것은 아니다.
- 활성 통화 0건·실행안 0건·실행 중 채팅 0건 확인 후 식별한 backend만 재시작했다.
- 실제 웹 새 대화에서 같은 일정 조회와 최근 메일 5개 요약을 다시 실행했다.
  두 assistant 메시지 모두 `completed`, `error_code=null`로 저장됐다.
  새로고침 후 완료 안내 2개, 오류/재시도 버튼 없음, 두 답변 본문 복원을 확인했다.
- 실제 등록·메일 발송·전화 발신은 없었다. 기존 실패 기록은 수정하지 않았다.
