# 자동 종료 후속: 요청·취소 기록과 재판단

상태: completed (모사 검증). 승인: 2026-09-27 자율 작업에서 사용자 ‘둘 다 포함해 주세요’.
실제 발신/유료 모델 호출 없이 모사 검사만 수행한다. 이전 실제 통화의 원인은 자료 부족으로 확정하지 않는다.

## 확인한 코드 경로

LiveBridge는 상대 음성이 다시 감지되면 `ending=None`으로 종료 예약을 취소한다.
취소 사실을 기록하거나 다시 종료를 판단하는 경로가 없었다. Live가 새 위임을 하지 않으면 대기가 지속될 수 있다.
25초는 종료 요청이 남아 있을 때의 재생 확인 상한이며, 종료 도구 호출을 대신하는 타이머가 아니다.

## 변경

- 종료 요청/상대 발화로 취소/재생 확인 완료·미확인 이벤트를 비식별 메타데이터로 저장.
- 상대의 추가 발화는 계속 보호. 단순히 타이머로 업무 성공을 가정하지 않는다.
- 새 전사가 있고 양쪽이 조용한 때 DeepAgents가 완료 여부를 보조 점검한다.
  최소 통화 10초, 무음 3초, 검토 간격 10초, 통화당 최대 12회. 같은 전사 버전은 한 번만 검토.
- 기존 위임/사용자 질문/조건 전달이 진행 중이면 보조 점검하지 않는다. 보조 점검에는 end_call만 제공.
  미완료는 조용히 계속 통화하며 새 질문·ARS·외부 조회/변경을 유발하지 않는다.
- 상대 발화/새 전사/새 조건/직접 종료/새 위임이 검토 도중 발생하면 오래된 종료 판단을 버린다.
  정상 위임도 종료 도구 호출 후 최종 답변을 만들던 중 상대 발화가 재개되면 오래된 종료를 버린다.
- 종료가 필요하다고 판단했을 때만 기존 마지막 인사→실제 송신 음성 ACK→회선 종료 절차 사용.
  모델 판단과 실제 재생/회선 종료는 여전히 별개이며 UI도 구분한다.

## 검증

종료 요청→상대 발화 취소→추가 답변→보조 점검→인사 ACK→종료 모사 통합.
진행 중 사용자 질문·상대 말하기·오래된 판단·종료 오류·검토 횟수/간격 제한·직접 종료 우선순위 회귀.
실제 모델의 완료 판단 정확도/청취 품질/실회선 자동 종료는 이 검사로 증명하지 않는다.

## 결과

- 종료 요청·취소·재생 상태를 저장하고, 새 대화 내용에 대한 제한된 완료 보조 점검을 추가했다.
- 종료 요청 후 상대 발화로 취소 → 추가 전사 → DeepAgents end_call → 인사 음성 ACK → audio_drained를
  실제 coordinator/bridge와 합성 미디어로 검사했다. 사용자 질문과 새 조건은 점검보다 우선한다.
- 진단 DB 저장 중 다시 상대가 말하는 경합도 재현하고 마지막 종료 직전 재검사로 보호했다.
- 전체 backend 233개 통과 뒤 진단 경합 회귀 1개를 추가하고 해당 통화 그룹을 재검사했다.
  최종 제품 전체 검사 결과는 로컬 제품 마무리 계획에 기록한다.
- 실제 모델 호출·발신 없음. 이전 통화 원인 확정이나 새 버전의 실회선 종료 성공을 주장하지 않는다.
