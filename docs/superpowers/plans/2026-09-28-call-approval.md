# 발신 허용 목록 제거와 사용자 승인

상태: complete

사용자 요청: “저거 없애고 그냥 모든 번호로 전화 걸 수 있게해줘. 전화 실제 발신 전에
사용자 승인을 받는 절차도 하나 마련해주고”. 번호별 제한 제거와 매 발신 전 승인을 구현한다.
기존 통화 카드와 실행 확인 UI를 확장하는 범위이며 실제 시험 발신은 포함하지 않는다.

## 동작

- `CALL_ALLOWED_NUMBERS` 설정을 제거한다. 현재 ClawOps 국내 번호 형식 검사는 유지한다.
- 모델의 `start_phone_call`은 승인 대기 요청만 저장한다. 승인 도구는 모델에 제공하지 않는다.
- 카드에 수신 번호·목적·첫 멘트·질문을 표시하고 ‘승인하고 전화 걸기’ / ‘취소’를 제공한다.
- 소유자 세션의 승인 API만 승인 기록을 원자적으로 저장하고 통화 작업을 시작한다.
  카드 버전과 저장된 실행 내용을 고정하며 중복 승인·새로고침·재시도로 다시 발신하지 않는다.
- 30분 만료, 취소, 다른 소유자, 잘못된 Origin, 변경된 카드 버전은 발신하지 않는다.
- 승인 대기에는 외부 모델/회선 사전 연결도 하지 않는다. 서버 재시작은 발신하지 않고
  기존 미발신 요청을 취소한다. 기존 단일 통화 제한은 유지한다.

## 파일과 검증

1. 통화 설정·저장소·매니저·HTTP 승인 경로에 회귀 검사를 먼저 추가한다.
2. 승인 전 발신 차단과 원자적 승인, 최종 발신 claim의 승인 검증을 구현한다.
3. 기존 카드의 중립색·시스템 글꼴을 유지하고 번호와 승인 버튼에 시각적 우선순위를 준다.
   모바일·새로고침·중복 클릭·응답 유실 오류 상태를 검증한다.
4. 프롬프트·문서·설정 예시와 로컬 .env를 갱신한다.
5. 모사 backend/web/E2E 검사 후 활성 통화가 없을 때 로컬 서버·외부 공유 빌드를 갱신한다.
   변경 파일만 커밋한다. 실제 전화·Google 쓰기는 수행하지 않는다.


## 완료와 검증

- 기존 허용 목록 검사·설정 필드를 제거하고 로컬 `.env`에서도 해당 항목을 삭제했다.
- 승인 대기/만료 시각과 승인 시각을 저장한다. 소유자·버전·만료 확인, 원자적 승인,
  최종 `claim_dial` 승인 기록 확인으로 모델 요청과 실제 발신을 분리했다.
- 프롬프트와 모델 도구 설명에 웹 카드 승인 전에는 발신하지 않는다고 명시했다.
- Backend 337개 / web 단위 55개 / 브라우저 59개 통과. 만료 타이머의 React 순수성 검사
  지적을 수정한 뒤 lint/typecheck/build와 관련 브라우저 3개를 다시 통과했다.
- 모바일 390px 화면에서 카드 내용·승인/취소 버튼·새로고침을 확인했다.
- 활성 통화·채팅 0건 확인 후 DB와 설정을 Git 제외 경로에 백업하고 로컬 서버를 재시작했다.
- Cloudflare 주소에서 새 빌드와 실제 메인 모델의 승인 카드 생성을 확인했다.
  과거 허용 목록 밖의 합성 번호로 요청했고 승인 시각·발신 시도·공급자 통화 ID는 모두 비어 있었다.
  카드를 취소한 뒤 직접 승인 API 요청도 409로 거부했다. 테스트 대화는 정리했다.
- 실제 전화는 걸지 않았다. 승인 후 1회 발신·중복 차단은 모사 공급자 검사 결과다.
- 기존 단일 통화 제한과 국내 번호 형식 제한을 유지했다. 국제 번호 지원은 포함하지 않는다.
