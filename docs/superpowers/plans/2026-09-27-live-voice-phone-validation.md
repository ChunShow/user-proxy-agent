# 개선 음성 실회선 검증

상태: 1회 실통화 종료, 일부 검증 미완료·사용자 청취 확인 대기.
승인: 개선 버전이 괜찮다는 사용자 평가 후, 본인 번호로 짧은 대화·끼어들기·시간 정정·
자동 종료를 먼저 검증하자는 제안에 사용자가 “좋아 진행해줘.”라고 승인했다.

## 범위와 순서

1. 기존 본인 허용 번호(끝자리 9615) 1회만 발신한다. 자동 재발신 없음.
2. 서버와 ClawOps 발신번호/Live 연결을 점검한다. 선택한 개선 지시·marin·중계 보완을 유지한다.
3. 웹 새 대화에서 AI 도우미의 가상 일정 확인 테스트임을 밝히도록 요청한다.
   내일 오후 3시를 제안하고 사용자가 정정한 날짜/시간을 따라 재확인한다.
   사용자는 필요할 때 발화 중 끼어들 수 있다. 실제 일정·메일 작성이나 조회는 하지 않는다.
4. 최종 답변이 확인되면 짧게 인사하고 자동 종료한다. 사용자 종료 요청은 즉시 따른다.
5. 전사상 정정 반영, 종료 근거, 회선 상태, 웹 자동 보고를 확인한다.
   자연스러움·끊김·끼어들기의 실제 청취는 사용자 피드백으로 별도 확인한다.
6. 결과와 한계를 문서·로드맵에 기록하고 로컬 커밋한다. 개인정보/전사는 Git에 넣지 않는다.

기존 제품 경로를 사용하며 코드 변경은 없다. 전체 자동 검사를 반복하지 않고 사전 점검,
실회선 기록, 웹 상태를 검증한다. 실제 청취가 미확인인 항목을 성공으로 확정하지 않는다.
Gmail 후속 작업이나 별도 음성 변경은 이번 발신 범위에 포함하지 않는다.

## 실행 결과

- 중단돼 있던 로컬 backend/web을 기존 dev 실행기로 백그라운드 시작했다.
  health 정상, 활성 회선 0건, ClawOps 발신번호 유휴·Live/control socket 연결을 확인했다.
- 웹 새 대화에서 본인 허용 번호에 1회 발신했고 약 55초간 연결됐다.
  gpt-live-1/marin과 현재 한국어 지시·중계 보완을 사용했다.
- 자동 전사에는 대기 요청에 대한 대기 안내, 재개 요청에 대한 설명 재개가 남았다.
  실제 말 멈춤 속도와 한국어 자연스러움은 전사만으로 판정하지 않는다.
- 가상 조건에 대한 최종 확인과 시간 정정은 완료되지 않았다. 위임/종료 도구 호출과
  종료 판단 보고는 없으며 직접 종료 API 요청도 없었다. media 종료 뒤 carrier completed를
  확인했고 결과는 incomplete다. 사용자가 직접 끊었는지는 청취 피드백으로 확인해야 한다.
- 웹 자동 결과 보고가 표시됐다. 추가 발신·Google 작업은 하지 않았다.
- 첫 입력 음성 기준 서버 계측: 첫 모델 음성 738ms, 첫 전송 846ms, 첫 재생 ACK 1013ms.
  이는 대화 응답 지연이나 끼어들기 지연의 측정치가 아니다. 입력 발화/끼어들기 카운터 0은
  Live의 이벤트 계측 한계로 성공/실패 판정에 사용하지 않는다.

실회선 자연스러움과 끼어들기 청취 평가는 사용자에게 요청했다. 이번 실행에서 시간 정정·
자동 종료를 검증 완료했다고 표현하지 않는다. 사용자 피드백 없이 자동 재발신하지 않는다.
