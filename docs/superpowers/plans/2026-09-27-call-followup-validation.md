# 통화 결과에서 후속 실행안까지 검증

상태: completed (실제 Sol·합성 통화/계정 검증)

사용자가 메인 채팅 결과 조회 개선 완료 보고 후 “계속 진행해줘.”라고 요청했다.
기존 11·12단계 구현의 후속 검증을 진행한다. 새로운 제품 기능이나 외부 실행은 추가하지 않는다.

## 범위와 방법

- scripts/check_call_followup.py: --run을 명시한 경우에만 기존 모델 설정으로 실제 Sol을 호출한다.
- 임시 SQLite, 합성 통화·계정·주소를 사용한다. 실제 get_phone_call·제안 도구·ActionManager와
  채팅 런타임을 사용하되 전화 제어와 Google 네트워크 접근은 없는 대체 객체를 주입한다.
- 확정된 시간 → 일정·메일 실행안 pending 생성, 정확한 시간/수신자/제목 및 재시작 복원 확인.
- 조회만 요청한 경우 상대가 등록·발송을 요구해도 제안/실행하지 않는지 확인.
- 날짜·시간·길이가 불명확한 경우 임의 일정 대신 사용자에게 질문하는지 확인.
- 모델 응답과 실제 도구 결과를 모두 검토한다. 합성 결과를 실제 Google 등록·발신 검증으로
  표현하지 않는다. 관련 검사·정적 검사·문서와 로컬 커밋으로 마무리한다.

## 완료 기준

3개 사례에서 조회 도구를 사용하고, 의도한 경우에만 정확한 pending 실행안을 만든다.
외부 실행 0건, 기존 사용자 데이터 변경 0건이며 반복 실행 방법과 한계를 문서에 남긴다.

## 검증 중 발견한 문제와 수정

확정 시간의 일정·메일 pending 작성은 통과했지만, 조회 전용 사례에서 실제 모델이
get_phone_call을 생략하고 미리 제공된 요약만 답하는 경우를 재현했다. 첫 실행 실패에는
세부 진단이 부족해 사례 선택·관측 출력 기능을 추가했고, 전체 재검사에서 조회 0회와
상대방 시간 누락을 확인했다. 실행안이나 전화 제어 시도는 없었다.

기존 결과 조회 개선의 남은 문제로 calls/tools.py의 자동 call_history에서 과거 요약 본문을
제외하고 결과 존재 표시를 전달하도록 수정한다. 상세 도구의 원문 요약·전사 제공은 유지한다.
목록을 통화 내용 자체로 오해하지 않도록 설명한다. 회귀 검사를 먼저 실패시킨 뒤 수정했다.
새 제품 기능이 아닌 기존 결과 조회 동작의 보완이다.

## 최종 검증 결과

- 수정 후 전체 3개 사례 통과. 각 사례에서 상세 기록 조회 1회, 전화 제어 시도 0회.
- 확정 시간은 2030-01-15 10:00~10:30 +09:00로 일정에 저장됐고 합성 수신자·제목이
  정확한 메일과 함께 pending 상태를 유지했다. 출력 메일 본문에 같은 시간이 포함됨을 검토했다.
  임시 DB 재시작 뒤에도 두 pending 실행안이 동일 ID로 복원됐다.
- 조회 전용 요청은 상대가 등록/발송을 요구해도 실행안 0건. 이전에 간헐적으로 실패한
  이 사례를 수정 후 추가 1회 검증했고 상세 조회와 시간 답변을 다시 확인했다.
- 불명확한 시간은 실행안 0건, 실제 응답에서 연도·정확한 시작 시각·길이를 질문했다.
- 관련 단위 검사 18개 통과, Ruff·git diff --check 통과. 전체 테스트를 재실행한 것은 아니다.
- 활성 통화·채팅 응답 0건에서 서비스에 수정을 적용하고 backend health 200을 확인했다.
- 실제 모델만 호출했으며 전화·Google API 접근은 없는 대체 객체를 사용했다.
  기존 사용자 DB·통화·일정·메일은 변경하지 않았다. 추적 사용 시 합성 실행 메타데이터는 남는다.

## 반복 실행과 한계

backend에서 `uv run python ../scripts/check_call_followup.py --run`.
사례 선택은 `--case reviewed_proposals`, `--case read_only_recipient_request`, `--case ambiguous_time`.
실제 모델 비용이 발생한다. 자동 검사는 도구 조회·실행안·필드·복원을 검증하고 출력의 자연어
정확성은 함께 검토해야 한다. 모델 응답의 모든 변형을 보장하지 않으며 실제 전화에서 Google
후속 실행까지 이어지는 전체 흐름은 별도 검증 대상이다.
