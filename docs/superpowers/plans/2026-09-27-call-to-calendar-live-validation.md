# 통화 결과에서 실제 일정 등록까지 검증 계획

> 직접 순차 실행한다. 병렬 에이전트를 사용하지 않는다.

**Goal:** 실제 통화에서 얻은 시간 정보를 같은 대화의 확인 카드로 옮기고 승인 후 Google 일정 1건으로 등록한다.
**Architecture:** 기존 GPT-Live/DeepAgents 통화, 자동 보고, Calendar 제안·웹 승인 경로를 사용한다.
**Tech Stack:** 기존 웹·FastAPI·SQLite·Google Calendar·Langfuse.
**Spec:** docs/product.md의 동일 대화에서 결과와 후속 업무를 이어가는 경험.

상태: in_progress. 구체적 실통화 시나리오와 등록 전 카드 확인 절차를 제시한 뒤
사용자가 “진행해줘.”라고 승인했다. 아래 범위의 1회 발신·등록안 준비를 진행한다.
새 제품 동작 변경이나 음성 프롬프트 변경은 이 단계에 포함하지 않는다.

## 첫 실행의 구체적 범위

- 대상: 기존 본인 테스트 번호(끝자리 9615), 전화 1회, 재발신 없음.
- 테스트 시간: 2026-09-28 10:00~10:10 Asia/Seoul. 실행 시 이미 지난 시간이면 먼저 재설정한다.
- 시작: AI 도우미임을 밝히고 실제 약속이 아닌 기능 검증임을 알린다.
- 질문: 해당 시간에 10분간 가상의 테스트 일정을 잡아도 되는지 확인한다.
  거절·불명확하면 임의로 동의 처리하지 않고 종료 결과를 보고한다.
- 통화 종료 후 메인 채팅에 확인된 날짜·시간·길이를 근거로 등록안을 요청한다.
- 제목: [연동 테스트] 통화 결과 일정 등록. 설명은 실제 약속이 아닌 검증용임을 명시한다.
- 기본 캘린더 1건, 참석자·초대·반복 없음. 자동 보고는 등록을 실행하지 않는다.
- 생성된 실제 확인 카드의 계정·날짜·내용을 검토한 뒤 사용자가 승인한다.
  카드가 나오기 전 포괄적 등록 승인을 요청하지 않는다.
- Gmail 전체 흐름은 이 결과 이후 다음 작은 검증 단위로 준비한다.

## 작업과 완료 기준

- [x] 사전 점검: 기존 실제 Sol + 합성 통화 reviewed_proposals 검증. 전화·Google 접근 없는 대체 객체 사용.
- [x] ClawOps 준비·활성 회선 0건 확인 뒤 웹 새 대화에서 1회 발신.
- [x] 답변 전사와 자동 종료·결과 보고를 확인하고 불명확한 사실은 사용자에게 확인.
- [x] 같은 대화에서 정확한 일정 확인 카드 pending 1건 생성. 모델이 임의로 실행하지 않음.
- [ ] 카드 승인 후 succeeded 및 Google 원본의 정확한 시간/제목/참석자 없음 확인.
  결과 unknown이면 자동 재실행하지 않고 원본부터 조회.
- [ ] 새로고침 후 같은 카드/결과 복원과 중복 일정 없음 확인. 테스트 결과물은 삭제하지 않음.
- [ ] 이 문서·로드맵에 결과와 제한 기록 후 로컬 커밋. 원문 전사·개인정보·토큰은 Git 제외.

## 파일·검증 경로

기존 scripts/check_call_followup.py, calls/tools.py, actions/manager.py, 웹 확인 카드를 사용한다.
사전 검사: backend에서 `uv run python ../scripts/check_call_followup.py --run --case reviewed_proposals`.
브라우저는 CUA로 검증한다. 코드 변경이 없으면 전체 자동 검사를 반복하지 않는다.
결함 발견 시 재현과 수정 범위를 먼저 기록하고 기존 승인 범위에 해당하는지 확인한다.

일정과 메일 실행안 각 1건을 정확한 합성 시간으로 만들었고 pending을 유지했다.
전화 제어 시도 0건, Google 요청 0건, 사용자 영구 데이터 변경 없음.
실회선·실제 Calendar 등록까지 검증한 결과는 아니다.


## 실회선·확인 카드 검증 결과 (등록 승인 대기)

2026-09-27 승인한 본인 번호에 웹으로 1회 발신했다. 시작 전 활성 회선 0건,
ClawOps 발신 준비·Live 제어 연결 검사를 통과했다. 통화 기록에서 제안한 가상 일정에
대한 긍정 답변과 날짜·시간 재확인을 확인했다. 원문 전사와 개인 식별자는 Git에 넣지 않는다.

직접 종료 요청 없이 goal_achieved → 최종 안내·인사 → audio_drained →
carrier completed를 확인했다. 종료 요청부터 재생 조건 충족까지 10.643초였으며
최종 안내 재생 시간을 포함한다. 활성 회선은 0건이고 오류 코드가 없다.
자동 보고 completed와 같은 채팅의 결과 표시를 확인했다. 실제 청취 확인은 별도이며,
초반 전사에는 발화 겹침이 나타나 이후 음성 품질 단계에서 다룬다.

같은 대화에서 실제 Sol이 get_phone_call로 기록을 조회한 다음
propose_calendar_event로 기본 캘린더용 pending 1건을 생성했다.
제목·설명·한국 시간 시작/끝이 위 범위와 일치하며 결과는 비어 있다.
웹 새로고침 후 같은 통화 결과·확인 카드가 복원됐고 추가 발신이나 메일 작업은 없었다.
Langfuse에서 통화 요청 18개, 제안 요청 6개 observation이 모두 종료됐으며
원시 입출력 기록은 비어 있음을 확인했다.

실제 카드 내용을 제시하고 사용자의 등록 승인을 요청했다. 현재 Google 등록 전이며,
성공 결과·Google 원본 조회·등록 후 중복 없음 검증은 남아 있다. 카드 유효기간은 30분이다.
제품 코드 변경이 없어 전체 자동 검사는 반복하지 않고 실제 UI·DB·추적 기록과 문서 diff를 확인했다.
