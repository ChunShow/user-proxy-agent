# 로컬 실행과 복구

프로젝트 루트에서 `./scripts/dev.sh`를 실행한 뒤 http://127.0.0.1:5180 을 연다.
종료는 실행한 터미널에서 Ctrl-C, 재시작은 종료가 끝난 뒤 같은 명령을 사용한다.
포트 사용 중 오류가 나면 기존 실행 터미널을 확인한다. 임의의 프로세스를 포트만 보고 종료하지 않는다.

## 연결이 끊겼을 때

1. 실행 터미널에서 서버가 살아 있는지 확인한다. 종료됐다면 위 명령으로 다시 시작한다.
2. 웹 우측 상단 서버 상태 버튼을 누른다. 정상 상태는 `서버 연결됨`이다.
   이 표시는 마지막 연결 확인 결과이며 자동 상태 감시나 외부 모델/Google 연결 확인은 아니다.
3. 대화의 `다시 불러오기`, 사이드바의 `목록 다시 불러오기` 등 오류가 난 영역을 다시 조회한다.
   서버 상태 버튼만으로 모든 영역을 다시 읽지는 않는다. 전송 전 초안이 없다면 새로고침도 가능하다.
4. 통화/실행 카드는 저장된 상태를 확인한다. 과거 채팅의 “접수/확인 대기” 문장보다 현재 카드
   상태가 최신이다. 조회와 새로고침은 새 전화나 메일 발송을 요청하지 않는다.

서버 연결 확인은 5초, 일반 데이터 요청은 15초 뒤 시간초과된다. 전송 전 초안은 탭 메모리에만
있어서 새로고침하면 사라진다. 같은 Chrome 프로필과 `127.0.0.1` 주소를 유지한다.
브라우저 쿠키를 지우면 기존 대화 접근이 복구되지 않으므로 연결 문제 해결 목적으로 지우지 않는다.

## 중단된 작업의 의미

| 작업 | 복구 동작 | 다음 행동 |
| --- | --- | --- |
| 채팅 응답 | 저장된 부분 응답을 실패/중단 상태로 복원 | 재시도 버튼이 제공되면 원하는 경우 직접 재시도 |
| 전화 접수 결과 불명확 | 자동 재발신하지 않고 미확인 상태 유지 | ClawOps 기록과 현재 회선을 먼저 확인 |
| 진행 중이던 전화 | 기존 공급자 통화 ID로 상태 확인·회선 정리 | 새 통화를 만들지 않고 기존 카드 상태 확인 |
| 메일/일정 실행 결과 불명확 | `실행 여부 확인 필요`; 자동 재전송 없음 | Gmail/Calendar에서 실제 결과 확인 후 새 요청 여부 결정 |
| 확인 대기 카드 | 원래 실행안 복원, 30분 기한이 지나면 만료 | 내용을 다시 확인해 직접 실행하거나 새 실행안 요청 |
| 통화 결과 보고 | 생성 중 끊긴 보고는 고정 안내로 복구; 미시작 보고는 처리 가능 | 통화 카드의 상태·내역 확인 |

재시작이 모든 외부 네트워크 접근을 없애는 것은 아니다. 기존 통화 상태 확인/정리나 대기 중인
결과 보고 생성은 수행될 수 있다. 새 발신과 Google 쓰기를 자동으로 반복하지 않는 것이 원칙이다.
실제 통화/메일/일정 실행 중에는 가능하면 서버를 정상 종료하기 전에 해당 작업을 마친다.

## 백업

서버를 정상 종료한 뒤 `data/` 전체와 `.env`를 비공개 위치에 함께 보관한다.
`data/integration.key`는 Google 연결 토큰 복호화에 필요하므로 DB와 함께 유지한다.
실행 중 DB를 백업해야 하면 파일 단순 복사 대신 SQLite backup API를 사용한다.
백업 파일에는 대화와 계정 연결 정보가 있으므로 저장소에 커밋하지 않는다.

복원은 서버를 멈추고 현재 데이터도 따로 보관한 뒤 진행한다. 오래된 백업은 외부에서 이미
완료된 발송/등록을 모를 수 있으므로 백업 복원 후 미완료 카드를 바로 재실행하지 않는다.
DB 백업은 브라우저 쿠키를 복구하지 않는다.

## 검증

`./scripts/check.sh`는 모델·공급자를 모사하고 로컬 자격증명을 배제한다.
2026-09-27 기준 백엔드 313개·웹 36개와 정적 검사/빌드를 통과했다.
실제 로컬 서버 응답 정지/재개와 정상 재시작 후 저장 데이터 보존도 확인했다.
실제 통화나 Google 실행 중 장애 시험은 하지 않았다.
