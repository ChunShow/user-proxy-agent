## 단계 검증 기록 방식

각 계획에 실행한 명령과 결과, 화면 또는 실서비스 확인 결과, 남은 제한을 남긴다.

후속 본인 통화 1회에서 전사상 최종 인사 1회, 종료 요청 후 7.2초의 재생 조건 충족과
회선 종료, Langfuse 16개 observation과 웹 새로고침 복원을 확인했다. 사용자도 인사 한 번 후 자동 종료됐다고 확인했다.
이미 인사한 분기의 실회선 검증은 남아 있다. 종료 결정 당시 요약 표시 문제는 아래 후속 개선에서 다뤘다.


[종료 결과 시점·확인 범위 표시](superpowers/plans/2026-09-27-call-result-wording.md):
요약의 작성 시점을 명시하고 새 요약에서 인사·회선 제어 메모를 제외하도록 지시했다.
업무 판단과 음성 전송·무음 확인, 실제 청취 여부를 구분한다. 웹 28개·관련 backend 14개,
실제 Sol 합성 전사 2개와 웹 기록 복원을 확인했다. 추가 실제 발신은 없었다.

같은 결과 표시 후속 검증에서 메인 채팅이 과거 요약만 재사용하는 문제를 재현·수정했다.
get_phone_call에 요약 시점·종료 근거·제한된 최근 자동 전사를 제공하고 실제 웹 재조회 응답과
Langfuse 도구 호출을 확인했다. 관련 테스트 25개 통과, 추가 발신·Google 작업 없음.


[통화 결과 → 일정·메일 실행안 검증](superpowers/plans/2026-09-27-call-followup-validation.md):
실제 Sol과 합성 통화·임시 DB에서 정확한 실행안 2건의 확인 대기·복원, 조회 전용 요청의
실행안 없음, 불명확한 시간의 추가 질문을 확인했다. 조회를 생략하고 과거 요약만 재사용하던
경우를 재현해 자동 문맥을 기록 목록으로 제한했다. 관련 검사 18개와 모델 3개 사례 통과,
간헐 실패 사례 추가 1회 통과. 실제 전화·Google API 실행은 없었다.


[통화 결과 자동 보고](superpowers/plans/2026-09-27-call-result-notification.md): 완료.
새 terminal 통화를 원래 채팅에 한 번 보고하고, 모델 실패·재시작에도 중복을 방지한다.
일반 채팅 스트리밍·초안·재시도를 유지한다. backend 286개·웹 32개와 정적 검사/빌드 통과,
실제 Sol 합성 기록 생성과 CUA 모바일/동시 응답/새로고침 복원을 확인했다.
최초 구현 검증은 실제 발신 없이 진행했으며 이후 실회선 검증 결과는 다음과 같다.

후속 본인 실통화 1회에서 직접 종료 요청 없이 audio_drained와 carrier completed를 확인했다.
종료 후 약 2.2초 만에 자동 보고가 저장·표시됐으며 새로고침 후 1건 복원과 Langfuse의 같은
요청 연결을 확인했다. 활성 회선 0건, 추가 발신·Google 작업 없음. 사용자도 “네, 인사 한 번 후 자동 종료됐어요”라고 확인해 이번 실통화 검증을 마쳤다.


## 다음 순차 작업

사용자가 남은 작업을 순차 진행하도록 요청했다. 첫 단위는
[통화 결과 → 실제 Calendar 등록](superpowers/plans/2026-09-27-call-to-calendar-live-validation.md)이다.
실제 모델·합성 기록의 사전 검사에 이어, 승인받은 본인 실통화 1회에서 가상 일정 동의와
자동 종료·결과 보고를 확인했다. 같은 채팅의 기록 조회 → 정확한 Calendar 확인 카드 1건
생성·새로고침 복원을 확인했다. 이후 사용자가 실제 카드를 승인하여 Google 등록을 완료했고,
원본의 정확한 시각·내용·참석자/반복 없음·중복 없음과 완료 카드 복원까지 확인했다.
이후 사용자가 음성 개선을 먼저 요청해 전화 없는 실제 API 비교를 진행했다.
[한국어 음성 1차 개선](superpowers/plans/2026-09-27-live-korean-quality.md):
9개 유효 실행의 전후·음성 비교와 58개 회귀 검사를 바탕으로 한국어 대화/끼어들기 정책을
적용했다. 기본 marin 유지, gleam/meridian 선택 가능. 실제 청취 품질과 간헐 공급 공백 원인은
미확정이며 비교 음성을 제공했다. Gmail 후속 실행 검증은 이 작업 뒤로 둔다.
Live 끼어들기와 한국어 자연스러움에 대한 추가 질문은
[공식 문서·코드 조사](research/2026-09-27-live-interruption-korean.md)에 기록했다.
조사 후 적용·검증 범위와 남은 제한은 [1차 실험 결과](research/2026-09-27-live-korean-experiment.md)를 따른다.

사용자가 개선 지시의 marin 샘플을 선택했고, 후속 요청에 따라
[음성 공급 공백 개선](superpowers/plans/2026-09-27-live-playout-continuity.md)을 적용했다.
시작/저음량 구간에 짧은 출력 여유분을 확보해 저장 기록 10개에서 재현된 43~103ms 공백을
40ms 이하로 줄이고 전체 바이트를 보존했다. 실제 API 1회와 통화 회귀 206개를 검증했다.
추가 전달 지연은 실행별 중앙값 62~170ms이며 실회선 청취 개선은 아직 확인하지 않았다.
선택한 marin·한국어 지시는 유지하며 추가 발신은 없었다.

후속 [개선 음성 실회선 검증](superpowers/plans/2026-09-27-live-voice-phone-validation.md)에서
본인 번호에 1회 연결했고 대기·재개 요청에 대한 응답과 웹 결과 보고를 확인했다.
약 55초 뒤 회선이 종료됐으며 시간 정정·자동 종료 도구 경로는 완료되지 않았다.
사용자가 직접 종료했고, 말을 알아듣지만 끼어들어도 적절히 멈추지 않았다고 확인했다.
끼어들기 품질은 실패로 기록하며 시간 정정·자동 종료는 미검증이다.
다음 제안은 [Live 재생 중단·재개 제어](superpowers/plans/2026-09-27-live-barge-in-control.md)다.

사용자가 해당 계획을 승인해 로컬 발화 감지와 실제 재생 중단/폐기/재개 제어를 적용했다.
최종 실제 API 합성 입력에서 300~382ms clear, 단일/연속 정정과 대기 후 재개를 확인했다.
짧은 맞장구는 중단하지 않았고, 통화 회귀 217개·웹 33개와 정적 검사/빌드가 통과했다.
실회선 지연·에코·사용자 청취 및 자동 종료 재검증은 남아 있다. 추가 실제 발신은 없었다.

이후 승인된 본인 실통화 1회에서 중단/재개 1회가 기록됐고, 사용자가 적절히 멈췄다고
확인했다. 종료는 자동으로 처리됐다는 취지의 사용자 답변을 받았다. 서버에서는 재생 조건
충족(audio_drained, 종료 요청 후 7.223초)과 회선 completed, 웹 결과 보고를 확인했다.
별도 carrier_hangup_requested 이벤트는 없으므로 정확한 회선 종료 주체는 로그만으로
확정하지 않는다. 가상 시간에 동의한 대화여서 시간 정정은 미검증이다. 연속 끼어들기·
소음/에코·실회선 반응 지연과 종료 경로 추적 보완은 후속 항목으로 남긴다.
