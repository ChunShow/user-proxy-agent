# 통화 승인 카드 문맥 평가

모델: `gpt-5.6-sol` (현재 서비스 설정). 실제 모델 API를 호출하되 임시 DB와
`ProposalOnlyManager`로 통화 공급자 접근·발신 승인을 차단했다. Google 도구는 연결하지 않았다.
합성 이전 대화와 확인 질문을 제공하고 마지막 답변에 대한 실제 모델/도구 실행을 평가했다.

| 사례 | 확인 결과 |
| --- | --- |
| 날짜 질문에 “내일” | 승인 대기 카드 1건 |
| 이름 질문에 이름만 답변 | 승인 대기 카드 1건 |
| 과거 카드 실패 후 “다시 해줘” | 승인 대기 카드 1건 |
| 번호 + “로 걸어줘” | 승인 대기 카드 1건 |
| 전화하지 말라는 취소 | 카드 0건, 생성 도구 호출 0회 |
| 통화 요금 문의 | 카드 0건, 생성 도구 호출 0회 |
| 이전 예약 대신 다른 업무 요청 | 카드 0건, 생성 도구 호출 0회 |
| 승인 대기 카드가 있을 때 재요청 | 기존 1건 유지, 생성 도구 호출 0회 |
| 승인 대기 카드 취소 | 기존 카드 canceled, 생성 도구 호출 0회 |
| 번호를 모르는 사용자 | 번호 확인 요청, 카드 0건 |

10개 모두 통과했다. 새 카드에는 사용자 제공 번호와 예약자 이름이 포함됐으며 모든 사례에서
승인 시각·발신 시각이 비어 있고 통화 공급자 접근은 0회였다. 모델의 응답은 확률적이므로
이 결과가 모든 표현의 의도 판단을 보장하지 않는다. 실제 발신은 별도 버튼 승인으로 보호한다.

## 실행

실제 모델 API 비용이 발생한다. 전화·Google 쓰기는 실행하지 않는다.

```sh
uv run --directory backend python ../scripts/check_call_card_context.py --run
```

한 사례만 실행하려면 `--case name`처럼 지정한다.

## 웹 확인

공유 주소에서 실제로 “번호로 내일 오후 1시 남자 커트 예약 전화해줘”를 입력했다.
모델의 성함 질문에 합성 이름만 답하자 날짜·시간·이름·목적이 포함된 승인 카드가 생성됐다.
새로고침 후 1건이 유지됐고 DB의 `approved_at`, `dial_attempted_at`, `provider_call_id`는
모두 비어 있었다. 승인 버튼은 누르지 않고 테스트 카드를 취소했다.

## 자동 검사

- 도구 경로 재현 8개: 후속 답변 5종, 오류 안내, 사용자/번호 소유권, 다른 턴의 중복 카드.
- 전체 backend 348개 및 변경 파일 Ruff 검사 통과.
- 전체 테스트는 `AGENT_SERVICE_ENV_FILE=/dev/null LANGFUSE_TRACING_ENABLED=0`으로
  로컬 운영 설정을 제외해 실행했다. 최초 운영 설정을 읽는 실행은 대기 상태로 중단했으며,
  격리 실행과 실제 모델 검증을 구분한다.
- 소유자·버전·취소·만료·중복 승인·미승인 발신 차단의 기존 회귀 검사를 유지했다.
- 일반 문의의 카드 생성 여부는 서버 명령어 정규식 대신 실제 모델 평가로 검증한다.
