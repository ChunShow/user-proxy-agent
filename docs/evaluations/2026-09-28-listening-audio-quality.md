# 가상 ARS 브라우저 청취 잡음 평가

실제 전화 발신·외부 음성 API 호출 없이, 로컬 합성 한국어 ARS 원본과 Chrome Web Audio로
청취 경로를 검증했다. 사용자 제보의 물리 청감을 직접 녹음한 결과는 아니다.

## 확인한 원인과 수정

1. 기존 플레이어는 매 패킷마다 `현재 시각 + 25ms`를 최소 재생 시각으로 적용했다.
   도착 지연이 있으면 이미 대기 중인 소리 뒤에도 불필요한 공백을 삽입했다.
   시작·버퍼 고갈 시에만 120ms 여유분을 확보하고 그 외에는 샘플 단위로 이어 붙인다.
2. 8kHz 원본 조각을 48kHz AudioContext에서 각각 재생하면 조각 경계에서 재샘플링
   오차가 생겼다. AudioContext도 8kHz로 맞춰 조각을 먼저 연결한다. 출력 장치의
   샘플률 변환은 전체 스트림에 적용된다. 이는
   [Web Audio 표준의 AudioContextOptions 동작](https://www.w3.org/TR/webaudio/#dictdef-audiocontextoptions)을 따른다.

두 수정은 브라우저의 읽기 전용 청취에만 적용된다. 통화 상대에게 보내는 음성,
모델 입력, ARS 음성 파일·μ-law 인코딩, 통화 중단 제어는 바꾸지 않았다.
시작 시 청취 여유분은 25ms에서 120ms로 약 95ms 증가한다. 장치·네트워크 지연은 별도다.

## 측정 방법과 결과

- ARS 원본 4개: 8kHz PCM peak 20,557~26,416, 포화 샘플 0개.
  μ-law 왕복 오차 기준 SNR 약 37.5dB. 이 전화 코덱의 오차 자체를 제거한 것은 아니다.
- `welcome.ulaw` 약 6.55초를 160바이트(20ms)씩 넣었다. 순서를 유지하며 0~50ms의
  가상 도착 지연을 반복했다. 실제 AudioBufferSourceNode를 OfflineAudioContext로
  렌더링하고, 최종 44.1/48kHz 출력을 단일 연속 음원 기준과 비교했다.
- 시작 지연을 맞춘 동일 음원과의 파형 오차 SNR이며, 음성 인식 정확도·MOS 점수가 아니다.

| 항목 | 수정 전 | 지터 처리만 수정 | 최종 수정 |
| --- | --- | --- | --- |
| 지터 입력의 재생 공백 | 2회, 합계 50ms | 0회 | 0회 |
| 일정한 입력의 파형 일치도, 48kHz 출력 | 28.1dB | 28.4dB | 96.1dB |
| 지터 입력의 파형 일치도, 48kHz 출력 | -3.2dB | 28.4dB | 96.1dB |
| 일정한/지터 입력 일치도, 최종 44.1kHz 출력 | — | — | 96.2dB |

두 번째 수정 전에도 공백은 0회였지만 파형 일치도 검사는 실패했다. 이후 같은 검사에서
통과하여, 재생 공백과 조각 경계의 변환 오차를 각각 구분했다. μ-law 디코더는 변경하지 않았다.
비교 WAV·측정 JSON은 Git 제외 `var/listening-quality/before/`, `after/` 및
`before-jitter.wav`, `after-jitter.wav`에 보존했다.

## 재실행

프로젝트 루트에서:

```sh
cd web
npm test
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e -- e2e/call-audio-quality.spec.ts e2e/call-listening.spec.ts
# 이미 준비한 로컬 ARS 원본을 평가할 때만 추가 지정:
PLAYWRIGHT_CHANNEL=chrome LISTENING_EVAL_CLIP=../var/simulator/audio/welcome.ulaw npm run test:e2e -- e2e/call-audio-quality.spec.ts
```

원본 파일을 지정하지 않으면 저장소 외부 파일이 필요 없는 합성 시험 신호를 쓴다.
기본 시험 신호는 시작/종료 경계가 급격하여 최종 변환의 오차가 더 크다(약 50dB).
테스트는 두 출력 샘플률에서 공백 없음·파형 일치도 45dB 이상을 요구한다.

## 검증과 남은 제한

- 웹 단위 검사 59개, 실제 Chrome 청취/파형 검사 3개 통과.
- 원본 ARS를 지정한 파형 검사도 두 출력 샘플률에서 통과.
- 타입 검사·lint·프로덕션 빌드 통과. 공유 HTTPS에서 새 빌드 파일의 바이트 일치 확인.
- 상대/도우미 독립 중단, 자원 해제, 긴 정지 뒤 재생 재개, 오래된 소리 대기량 제한 유지.
- 120ms 여유분을 넘어서는 지연·탭 중지에는 재생 공백이 남을 수 있다. 이때 전체
  통화를 늦게 재생하지 않도록 기존 대기량 상한 0.8초를 유지한다.
- 실제 스피커/이어폰 청감과 모바일 Safari 등 다른 브라우저의 물리 출력은 미검증이다.
  기존 통화는 중단하거나 새로고침하지 않았다. 사용자는 현재 통화를 마친 뒤 페이지를
  새로고침하면 새 플레이어를 사용한다.
